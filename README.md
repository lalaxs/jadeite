# 翡翠街 Jade Market Prototype

一个多人网页经营游戏原型。玩家在同一个本地服务器里参与翡翠公盘、加工经营、NPC 订单、收藏、直播和玩家交易。

## 当前核心流程

公盘竞拍 → 开料（opening）→ 规划取件（carving）→ 精加工（finishing）→ 藏品 / 订单 / 市场 / 直播

当前经营规则：交易行与黑市从开局开放，无成就积分门槛。工坊开料、规划、精加工均免加工费，镶嵌仍消耗金属和配石库存。

正式新账号自动领取 12,000 元和一块随机原石：糯种 70%、豆种 30%，重量 0.8～1.1 kg、原始参考价约 1,900～4,700 元。赠料只发一次，内部布局固定；限制高价值颜色并保证可取普通挂件，新手料及其加工产物失败退回阶段原料，时间和耐久正常消耗。首件赠料成品领取后出现「街坊试单」，按货值约 112% 收购。新手公盘门票 200 元；普通订单交付货值至少达到报价的 80%，含小费付款不超过交付货值的 125%。日课现金每日上限 1,000 元，首次引导期与成就共享 1,000 元现金预算，经验和材料照常领取。成品限额批发不受在线人数影响，每人每日最多 4 件、合计 6,000 元；立即回收仍为 20%。纾困不再登录自动发放，已有经营记录且符合条件的玩家可在账房申请含 5% 周转成本的借款。既有账号的现金、库存和已领取资源保持原样。

矿区暂不开放：导航、地点卡、竞租提醒和矿山调试入口隐藏，矿区操作接口统一拒绝请求。竞租轮次暂停推进，既有采矿任务继续结算，矿工、矿权及历史存档保留。后续可通过 `shared/domain/feature-availability.js` 中的矿区开关恢复开放，服务端修改后需重启生效。

员工采用一次签约费 + 登录日日薪，按北京时间自然日去重。登录当天记录员工名册与工资快照，在下一个登录日弹窗结算上次登录日；未登录日期不计薪，同一天重连、刷新、多窗口及重启不会重复扣款。持续在线跨天后，首次安排加工、开播、直播补货或招聘/解雇视为新营业日；仅挂机或被动收入不会触发结薪。1～10 阶日薪依次为 100、140、190、250、320、400、490、590、700、820 元，初始四名员工合计 1,500 元。新员工加入当日账单，解雇立即结清当天整日日薪并标记，后续登录不再重复收取。

登录结薪现金不足时整笔挂账，保留现有现金，宽限一个实际营业日，离线不消耗宽限期。下一个营业日先结算宽限日账单，仍未付清则暂停新工作且当天停止记薪。经营收入按 20% 补薪，与纾困还款合计不超过本笔收入的 30%；退款、保证金返还、纾困金、调试金和奖励不参与自动补薪。结清欠薪后由玩家主动复工，复工日记薪。结算弹窗持久保存至玩家关闭，员工页提供待结日期、补薪、复工及最近 10 次明细。本次迁移免除旧规则全部未付工资余额（旧存档无法可靠区分在线与离线部分），保留现金、员工、已付款历史和清理金额，从首次登录起重新记薪。

公盘每场 10 分钟，前 8 分钟明拍，展示当前最高出价，包含自己已提交的出价；最后 2 分钟暗拍，服务端不再下发他人最高价。自己的出价仍可查看、修改，结束后统一开标结算。

## 已实现的经营闭环

- 三阶段工坊：开料、规划取件、精加工。
- 工坊完工后保留待领取批次：在右侧「进行事项 → 工坊」启匣查看真实产物，再收入背包；多件取件与余料一同领取，开匣进度和离线产物均会保存。设备与员工在完工时立即释放。
- 每台设备容量永久固定为 1，同一设备不设等待队列。
- 设备商店：购买多个设备实例、固定 1 阶属性、耐久消耗与付费维修。
- 交易行二手设备：从工坊或挂牌弹窗出售闲置设备，支持购买与撤单，可卖空自己的全部设备；保留真实耐久、显示修满成本，买家另付 2% 市场税。加工中及被技术订单占用的设备不能出售。
- 员工系统：候选刷新、招聘、最多 8 人、跨工坊/直播占用、经验与技能升级。
- 黑市经营资源：玩家可挂牌、改价和撤回买入的员工与设备，其他玩家可直接转聘或购入；何叔人才行和老鲁设备铺提供全服共享、定期轮换的限量货源。员工保留技能经验，设备保留型号耐久，买入后直接进入名册或工坊。
- 黑市挂牌期间资源继续归卖方所有并暂停使用；员工仍占名额、按登录日计薪。转聘工资与历史欠薪由原雇主承担，离线成交不为其他员工开启新计薪日。初始赠送资源同样可转售，员工与设备均可全部售出，读档不会补发；员工与设备不进入盲盒。
- 黑市员工与设备卡片复用现有粗线条玉绿色插画、卡片配色与按钮，卡面保留两行摘要，技能、特质和维修参数在详情中查看。
- 手镯独立精修：基础出光、标准精修、匠心精修，耗时分别为基准的 0.75、1、1.5 倍；可选亮光、柔光，沿用取件圈口与玉料底稿，不消耗外部材料。按打磨60%＋修形40%评分。
- 挂件与蛋面精加工：成品类型、六种镶法、四种金属、三种配石、抛光与底托选择。
- 原子结算：开工时预占材料并支付人工费；组合无效、材料不足或现金不足不会产生部分扣款。
- 精加工失败会退回翡翠和镶嵌材料，人工费保留为已发生支出，设备耐久与员工经验正常结算。
- 藏品、订单和交易行统一显示成品镶嵌工艺摘要。

桌面端保留原有整体排版，已验证 1280×720 与 1440×900；移动端复用同一套 DOM，已验证 390×844 与 430×932。

## 规划草稿与经营账本

规划按当前浏览器、玩家和材料自动保存，支持撤销／重做及恢复上次完成版本；关闭、切料和开工失败保留布局，开工确认成功后清理。刷新后恢复布局，撤销历史从当前页面重新开始。

库存详情可查看已记直接成本，历史成本缺失保持未知。成本和成交记录保留在经营账本中；批次仍有在库、在制或待领取物品时不提前判定最终盈亏。完整说明及隔离验证入口见 [交付记录](docs/reports/2026-10-23-planning-finance/README.md)。

## 生产服务端

公开部署采用单权威 Node.js 游戏进程、PostgreSQL、Caddy 和每日校验备份。生产环境中的写操作会在数据库提交后才向客户端确认；保存失败会恢复操作前状态，不会向玩家展示未落盘的资产变化。

上线前执行：

```bash
npm run predeploy:check
```

并在临时真实 PostgreSQL 上执行：

```bash
TEST_DATABASE_URL='postgresql://...' npm run predeploy:postgres
```

生产配置模板位于 `.env.production.example`，容器编排位于 `compose.yaml`。服务器架构、运行操作和发布门槛分别见：

- `docs/server-architecture.md`
- `docs/operations-runbook.md`
- `docs/predeploy-checklist.md`
- `docs/server-deployment-plan.md`

正式服务器必须使用 PostgreSQL 驱动、HTTPS/WSS、精确来源白名单和独立管理令牌。生产环境不会注册加钱、解锁或刷物品等调试事件。

### 存档模式

默认继续使用 `data/world.json`，与旧存档完全兼容。需要启用事务型 SQLite 存档时，在启动前设置：

```powershell
$env:JADE_WORLD_PERSIST_DRIVER="sqlite"
npm start
```

SQLite 默认写入 `data/world.sqlite`，也可以通过 `JADE_WORLD_SQLITE_PATH` 指定路径。数据库第一次启用且还没有检查点时，会从 `JADE_WORLD_PATH`（默认 `data/world.json`）复制迁移现有存档；原 JSON 文件会保留不动。

SQLite 保存采用完整世界快照事务，并保留最近两代检查点。当前代校验失败时会自动尝试上一代。设置 `JADE_WORLD_PERSIST=0` 仍可完全关闭持久化，供隔离测试使用。

JSON 保存会先同步临时文件，再原子轮换备份和主档；支持目录同步的平台还会同步目录元数据。进程在写入中被强制终止时，残留临时文件不会覆盖上一份完整主档。SQLite 使用 WAL、完整同步和事务检查点，未提交写入会在重启时回滚。

### 矿务数值审核权限

正式环境可用英文逗号配置允许调整全服采矿数值的玩家 ID：

```powershell
$env:JADE_MINING_TUNING_REVIEWER_IDS="player-id-1,player-id-2"
npm start
```

配置后，只有这些账号可以审核正式版本、撤销排期或安排回滚。未配置时，为方便本地原型运行，会由首位矿区创始成员自动担任矿务数值审核员；其他玩家仍可使用影子观察，但只能查看正式版本。

## 重要说明

当前生产架构是“单区、单权威游戏进程”：已提供游戏内账号入口与多会话、PostgreSQL 周期检查点加增量日志、指令提交屏障、持久化就绪探测、指标、管理接口、有界审计、备份和优雅关机。本版不能直接水平扩容多个 Node.js 游戏容器；需要多副本时，必须先引入全局调度、事件总线与数据库并发控制。JSON/SQLite 仅用于本地开发、迁移和隔离测试，正式环境强制使用 PostgreSQL。
