# 翡翠街玩法与玩家体验审查

审查日期：2026 年 10 月 9 日。对象为当前工作区版本。

游戏已经具备较完整的经营功能，也能完成原料加工到直播回款的一轮操作。但新手经营闭环还不够可靠：订单题材与加工结果不兼容、交易行缺少货款领取入口、市场自动收购与挂牌承诺冲突，低价料的精加工成本又缺少有效提示。这些问题会让玩家把规则错误理解成自己的判断失误。当前最值得保留和强化的是观察料子、规划取件以及余料再加工，它们确实能让玩家通过判断改善结果。

## 试玩范围与实际结果

普通角色从 30,000 元、3 块初始暗料开始，使用正常生产和直播时长，没有增加现金、库存或成就积分。试玩环境关闭持久化，独立于原有游戏服务。高级系统使用另一名测试角色；矿区另开环境，将人数门槛改为 1、声望门槛改为 0，租期改为 180 秒、申请窗口改为 30 秒、开采改为 10 秒。这些高级测试只能证明流程与交互，不能代表自然解锁速度或正常矿区平衡。

| 环节 | 实际操作与结果 | 玩家感受 |
| --- | --- | --- |
| 初次进入 | 查看主页建议、成长目标、任务和 13 个功能入口 | 有下一步提示，但陌生概念过多 |
| 公盘 | 支付 800 元入场、100 元开窗，冻结 1,973 元投标，正常开标后中标 | 信息购买与竞价有经营味道，资金占用需要更清楚 |
| 开料 | 松花后江料由阿成处理，697 元，约 1 分 3 秒 | 操作能完成，揭露真实品质的反馈偏弱 |
| 规划 | 小周处理，首次 599 元，约 3 分 13 秒；取手镯与平安扣 | 题材、尺寸和摆位有真实取舍 |
| 余料再加工 | 继续处理带着原切口的余料，583 元；把小号平安扣从废料位置拖到适合的位置，预估价值 816 → 1,547 | 本次最明确的掌握感来源 |
| 精加工 | 林师傅处理三件毛坯，每件实际收费 1,130 元，约 1 分 33 秒 | 师傅能力强，但费用与低价料增值不相称 |
| 订单 | 检查四张初始订单及拒收预检；普通角色没有交成订单 | 能看到拒收原因，但可制作性存在系统错误 |
| 直播 | 买 10,000 元许可，攒三件成品，选许工，按估值定价 | 开播准备门槛高于首次卖货应有的门槛 |
| 完整销售 | 三件成品在 3 分 50 秒内售罄，营收 5,429 元，自动关播；现金到 21,475 元 | 有成交反馈与现金回流，结算“纯利润”口径错误 |
| 重连 | 直播期间刷新页面，再进入自己的直播间 | 房间和待售货品恢复，未丢失正在营业的状态 |
| 高级经营 | 测试角色完成交易行挂牌、黑市建摊与上架、收藏与取回、订单交付 | 基础操作能完成；调试生成的货不能证明正常加工订单可行 |
| 市场自动成交 | 等待挂单满十分钟，1,204 元挂单消失，账单显示待结算 663 元，现金没有增加 | 自动折价与挂牌承诺冲突，且货款缺少可用领取入口 |
| 矿区 | 在单独调整门槛和时间的环境申请白雾浅坑，支付 28,000 元租金、400 元工资，原石自动归仓 | 分配、派工、记录可衔接；普通环境的 50 席位门槛仍阻止小规模自然进入 |
| 手机布局 | 检查 390×844 与 390×667；桌面检查 1280×720 | 导航可滚动，但顶部控件遮住内容，规划操作空间偏小 |

生产时间是本次师傅和设备组合的报价，并非所有玩家的固定耗时。整个审查期间有大量停留和阅读，不能把审查总时长当作普通玩家的首单时长。现金余额包含奖励、许可、竞拍及其他资产变化，也不能直接作为这一块料的利润。

## 游戏设计要素满足情况

| 要素 | 判断 | 依据 |
| --- | --- | --- |
| 经营身份与题材 | 基本满足 | 公盘、料子、师傅、镶嵌、藏品有统一的翡翠经营背景 |
| 短期目标 | 部分满足 | 主页提供下一步；但第一件货完成后，便捷卖货渠道仍有门槛 |
| 有意义的决策 | 规划环节较好，其余不均衡 | 摆位改善价值和废料率；工资、风险、售价决策缺少同屏比较 |
| 风险与公平性 | 尚未满足 | 规则不兼容与自动折价不是玩家能够合理预判的经营风险 |
| 经济闭环 | 能直播回款，但存在关键缺口 | 正常生产结果多数不能匹配订单题材，收益标签不代表成本利润 |
| 成长与解锁 | 功能存在，目标感不足 | 经营经验、声望、客户评级、成就积分、员工技能并行，作用边界不清楚 |
| 放置体验 | 有等待与离线营业，自动化不足 | 每台设备容量 1、无等待队列；每一道工序都要重新安排 |
| 玩家反馈与学习 | 部分满足 | 规划有实时预估、订单有预检；加工完成缺少前后对比和损益解释 |
| 收藏与自由经营 | 基本满足 | 收藏可取回，余料可继续加工，也能选择订单、市场或直播 |
| 社交与竞争 | 机制存在，冷启动不足 | 公盘、排行、黑市、矿权竞争依赖活跃人口；本次没有验证真实多人博弈 |
| 手机交互 | 尚未满足 | 账号和昼夜按钮实际遮住工序页签；核心规划界面需要频繁滚动 |
| 长期留存 | 有潜力，需要后续验证 | 目前成长主要是数值与功能门槛，尚未通过多日真人试玩证明策略会持续变化 |

## 优先修正的不合理设计

### P1 精加工破坏题材，订单无法形成可靠闭环

正常精加工的成品类型是戒指、吊坠、耳坠、手链或把件；订单要求的却是蛋面、平安扣、佛公、叶子等题材。精加工同时覆写 `kind`，订单匹配又优先读取 `productType`。同一件平安扣，加工前可以满足平安扣题材，加工后变成 `pendant`，被拒收为“题材不符”。仅保留 `kind` 还不足以修复，需要同时调整订单的取值规则。

固定随机种子 20261009、以新手默认评级生成 2,000 张订单，1,856 张的题材不在正常精加工输出类型中，占该样本的 92.8%。这是当前生成器和类型契约的诊断样本，不是线上拒单率。十二种订单题材中，只有 `bracelet` 与正常精加工输出类型重合；手镯如果选把件仍会不匹配。

影响是玩家学会了“怎么做货”，却无法学会“怎么完成客户需求”。开发工具生成的旧题材成品能交单，会掩盖这一问题。应分别保存题材、佩戴类型和加工阶段，订单明确检查对应字段，并用同一份可制作目录约束订单生成。

证据：[加工覆写题材](/Users/jar/Documents/翡翠/jade-market-prototype/server/systems/inlay-system.js:348)、[题材匹配](/Users/jar/Documents/翡翠/jade-market-prototype/shared/domain/jade/jade-rules.js:185)、[成品分类取值](/Users/jar/Documents/翡翠/jade-market-prototype/shared/domain/jade/jade-rules.js:431)、[可复核的诊断结果](/Users/jar/Documents/翡翠/jade-market-prototype/docs/reports/2026-10-09-player-audit/order-feasibility-evidence.json)。

### P1 订单要求没有经过配方可行性检查

初始订单实际出现“手镯＋足金24K”和“珠串＋铂金”。现有整件形态只允许编绳，编绳又不能使用金属，所以这些订单无法完全符合要求。某些金属要求属于可折价的条款，不能把它们一律描述成完全无法交付，但满额目标确实不可达。同一批 2,000 张样本中，72 张出现整件形态与金属要求冲突，占 3.6%，与前述题材问题有重叠，不能相加。

试玩规划页提供七种套件，订单还可能索要如意、观音、福豆、葫芦或珠串。应让生成器先验证存在有效制作路线，再抽取品质、尺寸和工艺要求。高难订单可以需要买高档料或与别人交易，但界面必须区分“当前能力不足”和“当前规则根本做不出来”。

证据：[允许的形态与工艺](/Users/jar/Documents/翡翠/jade-market-prototype/server/systems/inlay-system.js:50)、[订单独立抽取题材和要求](/Users/jar/Documents/翡翠/jade-market-prototype/server/services/orders-service.js:713)。

### P1 市场自动收购低于玩家挂牌价

测试挂单的参考估值为 1,020 元，系统默认建议挂牌 1,204 元，确认页明确显示“卖家到账 1,204 元”。低人口流动性规则却允许在挂满 10 分钟后，按挂牌价与估值 65% 中的较小值自动收购，即这件货可能只形成 663 元待领取款。

等待满十分钟后，这条规则实际触发：挂单从“我的挂单”消失，账单出现待结算 663 元，现金没有增加。1,204 元与 663 元之间的差额为 541 元，并非买方另付的 2% 市场税。

有批发商提供流动性是好设计，但玩家填写的出售价格应得到遵守。应改为可接受或拒绝的批发报价，或在上架时让玩家主动选择自动折价并设置最低到手价。确认页必须显示这一选择及其金额。

证据：[低人口自动收购规则](/Users/jar/Documents/翡翠/jade-market-prototype/server/services/market-liquidity-service.js:9)、[实际成交金额计算](/Users/jar/Documents/翡翠/jade-market-prototype/server/services/market-liquidity-service.js:18)。

### P1 交易行成交款缺少可用领取入口

上述自动成交后，现金保持 544,325 元，账单显示“待结算 663 元”。实际检查交易行、主页、待处理事项及账单，均没有可用领取按钮；页面中也不存在 `collectPayouts` 操作元素。服务端领取功能仍在，前端动作也有注册，但产生按钮的旧 `statusRows()` 没有被当前主页渲染调用，原位置已经只显示完整排行入口。

这会直接阻断交易行回款：玩家的货离开了库存和挂单，钱却留在待收款状态。应在交易行和主页待处理事项中恢复明确的“领取货款”入口，显示金额与成交明细，领取后立即反映到现金及账单。也可以统一改成成交自动到账，但要同步修改所有提示、账单和待收款规则。

证据：[待结算货款截图](https://github.com/lalaxs/jadeite/blob/f26a1d5312e9bcf17546f1bae6fce47af7fdaa2e/docs/reports/2026-10-09-player-audit/12-market-pending-payout.jpg)、[未被当前主页调用的旧领取按钮](/Users/jar/Documents/翡翠/jade-market-prototype/public/features/overview/overview-render.js:118)、[当前主页渲染位置](/Users/jar/Documents/翡翠/jade-market-prototype/public/features/overview/overview-render.js:527)、[服务端领取实现](/Users/jar/Documents/翡翠/jade-market-prototype/server/services/market-service.js:494)。

### P1 手机顶部控件遮住核心操作

390 像素宽度下，账号和昼夜按钮落到顶部第二行，压在工坊“精加工”、商铺页签和主页内容上。测得顶部高度 54 像素，而工具区域从纵坐标约 63 像素开始。这是实际遮挡，不是纯粹的风格偏好。390×667 的导航本身可以滚动，不能把它误报为导航无法到达。

账号与主题操作应放入菜单或完整容纳在顶部；内容起点必须依据真实头部高度。手机规划页应独占可用宽度，让选套件、调尺寸、查看结果和确认动作围绕画布组织。桌面 1280×720 的规划石头底部也需要内滚动，应优先缩放画布以完整展示当前料子。

证据：[手机遮挡截图](https://github.com/lalaxs/jadeite/blob/f26a1d5312e9bcf17546f1bae6fce47af7fdaa2e/docs/reports/2026-10-09-player-audit/04-mobile-workshop-overlap.jpg)、[手机规划截图](https://github.com/lalaxs/jadeite/blob/f26a1d5312e9bcf17546f1bae6fce47af7fdaa2e/docs/reports/2026-10-09-player-audit/05-planner-mobile.jpg)。

### P2 默认精加工方案缺少经济判断

第一件手镯毛坯估值 1,654 元，实际精加工花费 1,130 元，成品估值 1,945 元。增值 291 元，相对毛坯直接按同一估值基准出售，增量收益为 −839 元。这个比较未分摊原料、前序工费、余料价值，也没有把可能存在的订单溢价算入，不能据此宣称整条生产链必亏。

另外两件毛坯的估值为 1,402 和 1,565 元，精加工后为 1,648 和 1,836 元，同样各支付 1,130 元。三件合计增值 808 元、精加工费用 3,390 元，默认高阶师傅对这批低价货的经济选择很差。游戏不需要让所有加工都赚钱，但应让玩家在开工前看懂为什么可能亏。

开工页应比较不同员工和工艺的费用、预计品质、增值及可交订单；“智能推荐”需要标明推荐目标。可以提供稳妥、低成本和追求品质三种推荐。首次低价料不宜默认使用高工资方案；毛坯出售、来料加工或加工委托也能让玩家拥有成本更合适的经营路线。

### P2 新手第一件货缺少便捷的回款路径

交易行需要 80 成就积分。普通角色完成这次六道工序、竞拍中标和首次直播成交后，仍为 60 积分。直播先要 10,000 元许可，且至少三件成品才能开播；订单又存在前两项问题。结果是第一件货到手时，玩家需要继续花钱加工更多货，或主动探索额外成就。

应在正常经济里提供一条可理解、可制作、可回款的首轮路径，例如允许新手单件寄售，或提供低价可制作的来料加工委托。保留公盘的不确定性和高档料的风险，让玩家先学会成本、产出、交付和回款，再学习规模经营。建议目标是熟悉流程的新手能够在前十分钟内获得一次经营回款，而非单纯领取任务现金。

### P2 直播“纯利润”标签与计算不符

本场三件货按估值卖出 5,429 元，弹窗显示纯利润 0 元。核对后，计算是成交金额减去成品估值，既不是实际购料成本，也没有计入加工费用。这并非把负数强行截为零，而是使用了错误的利润口径。

在成本尚未跟踪完整时，应改名为“售价相对估值的差额”。要显示经营利润，需要追踪原料成本、各工序人工、材料消耗和合理的多件成本分摊；许可等长期投入另列资产投资。矿区已经标明“估算净收益”，可继续保留估算，但最好同时展示本轮累计实际现金支出。

证据：[把成品估值记入成本](/Users/jar/Documents/翡翠/jade-market-prototype/server/systems/livestream-room-system.js:445)、[利润计算](/Users/jar/Documents/翡翠/jade-market-prototype/server/systems/livestream-room-system.js:290)、[本场结算截图](https://github.com/lalaxs/jadeite/blob/f26a1d5312e9bcf17546f1bae6fce47af7fdaa2e/docs/reports/2026-10-09-player-audit/10-live-settlement.jpg)。

### P2 多条成长线缺少清晰分工

经营等级、声望、客户评级、成就积分及员工技能同时出现。声望区域里的 `Lv.1` 实际来自经营等级，但矿区要求“声望 Lv.3（100）”，容易让人误判自己是否达标。首次主页优先展示现金峰值 50,000 元，也没有直接解释怎样到达最近的交易行解锁点。

应明确标成“经营等级”“声望”“客户评价”“成就积分”，在锁定入口给出当前值、差额、最近可完成的两项行动及解锁结果。把一次工序的工分、品质等级和种水分数分别解释，避免玩家把不同评价混成一条数值。员工的“易裂、易出绵”等缺陷描述也应说明如何影响作业，避免看起来像员工本人具有料子属性。

### P2 等待已有，放置经营的便利还不足

设备容量 1、没有等待队列，阶段完成后需要再次选择料子、人员、方案及开工。第一次选择应有参与感，反复做相同操作则会变成看倒计时与点确认。12 元的小额材料购买、开工等操作还会弹出需手动关闭的成功窗口。

把常规成功反馈改为不打断操作的提示，保留风险支出、陌生规则和不可撤销选择的确认。允许玩家保存方案、复用员工配置，并在成长阶段解锁短队列或重复派工。自动化可以负责执行已确认的决策，手动摆位、判断料子和选销售渠道继续保留给玩家。

### P2 风险与完成结果不足以支持学习

开窗有观察文本，但信息有限的结论缺少置信度和可比较的价值区间。设备显示风险倍率，玩家却不容易知道本次实际碎裂概率。工序完成主要进入库存和消息，没有把“我做了什么、结果变了什么、为什么”集中展示。

开工前展示本次风险、费用与预计区间，结果页对照初始估值、工艺、裂损、品质和增值来源。高风险失败仍应存在，但玩家应能分辨材料本身、员工、设备和摆位各自贡献。开料是题材最具悬念的一刻，值得增加清晰的品质揭露和简短结果回顾。

### P2 多人门槛与声望规则影响冷启动

普通环境的矿区要求 50 个有效竞租席位达到声望 100；个人继续经营不能独自填满全服人数。可以按活跃人口开放较小矿区，再逐步增加竞争矿口，或让玩家先参与独立采集，将稀缺好矿保留给多人竞租。

声望目前在线每十分钟衰减 0.5、下限 10，离线结算重置衰减时间。普通角色等待期间从约 12 变为 11。在线等待受衰减、离线不追算会产生不一致激励。单笔消费达万元又能获得声望，而低价直播单笔不足万元没有这类现金流声望奖励。应优先让诚信交付、质量和有效经营贡献声望；若保留衰减，应明确规则并统一在线与离线口径。

矿区流程本身比开工页更清楚，能直接看到事故风险 3%、工资、产出区间和自动归仓。这种表达值得迁移到工坊。

### P2 失败恢复与奖励激励需要更明确

系统存在救急垫款：现金低于 2,000 元且没有库存、材料、在途任务、待收款等资产时，下次连接补到 12,000 元，债务加 5%，后续收入偿还 10%，有三十分钟冷却。不能把本游戏描述成“没有兜底”。但任意少量镶嵌材料都会阻止救急，不以其价值判断；玩家不容易理解为何自己缺钱却不能恢复。

应在低现金时给出具体恢复路线和阻挡原因，明确回收价值、未收款、可交订单及债务。试玩中购买 1 克银仅花 12 元，却能推进奖励 1,600 元的材料采购任务。这可以作为一次教学奖励，但任务应解释下一步用途，避免玩家只为奖励买最少数量、忽略制作需求。工坊任务的“完成”口径也应统一为结算完成，避免开工即计数造成误解。

证据：[救急条件与债务规则](/Users/jar/Documents/翡翠/jade-market-prototype/server/services/recovery-service.js:8)、[少量材料阻挡](/Users/jar/Documents/翡翠/jade-market-prototype/server/services/recovery-service.js:40)。本次没有把普通角色主动耗尽资产来触发垫款，恢复结论来自规则核对。

## 值得推进的玩法优化

首先，把订单需求带入规划。玩家选择一张可制作订单后，规划页直接显示所需题材、尺寸、种水、净度和工艺，预估哪一块位置能满足要求。现在摆位已经有收益差异，加入客户目标后，选择会从“价值最高的位置”变成“这块料能服务哪个客户”。

其次，为同一块料提供几条经济路线：卖明料或毛坯、做低成本周转货、投入材料做高档定制、留下优质货收藏。把预计回款、加工投入和时间放在一起比较，既让谨慎玩家有选择，也保留追求稀有成品的风险与回报。无需保证每条路线赚钱。

再将员工和设备成长转化为新能力。除了更高工分和更快倒计时，可以解锁小批量加工、稳定净度的专项工艺、方案复用和委托代工，让投资改变经营方式。初始四位员工已经覆盖岗位，后续招募应让玩家看到扩产或压低成本的明确理由。

客户方面，可把现有年龄、财富、性格和动机沉淀成少量可记忆的常客。让好评影响复购、订单偏好和定制机会，拒收也解释具体偏差。直播评论应更多回应当前货品和售价，例如价格偏高、喜欢何种料子、为什么决定购买；现在通用点赞与留言能营造热闹，但给玩家的经营信息有限。

最后，让三个销售渠道承担不同角色。订单强调满足需求和建立口碑；交易行强调价格发现与等待；直播强调库存周转与主播配置。黑市可以进一步围绕盲盒信息、信誉与技术服务形成独有判断，不宜仅依靠更高的成就门槛。低人口环境需要可见、可选择的批发报价，冷启动时也能形成交易预期。

## 修改顺序与验收

第一批先修订单题材、订单配方、货款领取、市场折价授权及手机遮挡。第二批补齐新手第一笔回款、成本与利润口径、解锁指引。第三批再做自动化便利、常客、渠道差异与矿区人口适配。暂不建议继续堆叠新的经营系统。

| 验收项 | 应达到的结果 |
| --- | --- |
| 正常加工交订单 | 从暗料开料、规划平安扣、精加工为吊坠，再交对应平安扣订单成功；使用真实加工结果 |
| 生成器可行性 | 新生成订单存在有效题材、尺寸与工艺组合；整件禁止金属时不生成满额必须金属的目标 |
| 市场价格承诺 | 未选择自动折价的挂单不会低于挂牌价被 NPC 买走；折价必须显示最低到手价 |
| 市场回款 | 成交后可找到领取入口或自动到账；现金变化与账单、待收款金额一致 |
| 新手经济体验 | 新角色前十分钟可走完一条明确的生产或委托回款路线，不靠开发工具或任务现金伪装回款 |
| 加工方案比较 | 开工前能看出人工费、材料费、增值、目标订单及余额；推荐目标明确 |
| 结算口径 | 营收、估值差额、成本利润和资产投资分别表述，不把估值当成本 |
| 手机操作 | 390×667 和 390×844 顶部不覆盖正文；规划、费用与确认能在合理滚动范围内操作 |
| 风险反馈 | 失败或低品质结果能解释主要原因，玩家知道下一次可改变什么 |
| 恢复与成长 | 缺钱时有具体周转路线；锁定入口显示差额和近期可完成的解锁行动 |

现有体验回归、简化流程、经营循环和响应式检查均通过，三个试玩页面未捕获浏览器错误或警告。但其中的响应式检查是静态规则检查，订单测试也直接构造匹配题材的成品，不能代替正常加工到交付的端到端验证。应补上上表中的真实生产和价格承诺测试。
