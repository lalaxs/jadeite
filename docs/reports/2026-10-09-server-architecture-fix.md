# 翡翠街服务器架构审查修复版

本版落实 2026 年 10 月 9 日审查的 11 项问题，修复身份、提交、恢复和权限漏洞，并降低普通操作随存档玩家数量增长的开销。架构继续采用一个权威游戏进程和 PostgreSQL，没有新增微服务、消息队列、缓存集群或备用世界。

## 修复对应

| 审查项 | 修改后的行为 | 验证 |
| --- | --- | --- |
| R1 失效身份可被公开编号认领 | 移除编号认领；过期、撤销和无凭据账号均拒绝，有效旧哈希令牌可轮换 | 会话单测、真实连接与密码重新登录 |
| R2 检查点保存未提交状态 | 自动和手动检查点与指令共用调度队列，等待提交或回滚 | PostgreSQL 注入写入失败后保存、再重启恢复 |
| R3 请求编号冲突导致恢复日志漏记 | 去重保持每名玩家最近 200 个编号；迁移 004 移除日志与审计的全服唯一索引，不再静默跳过变更 | 跨玩家同编号、201 次操作后的淘汰与重用、重启与投影一致性 |
| R4 状态读取和断线越过提交边界 | 初始状态、重新取状态和广播在读取队列内生成；立即解绑断线连接，排队记录离线时间，回滚不恢复旧连接 | 阻塞写入期间读取和检查点等待、双人交易回滚、断线不复活 |
| R5 退出后旧连接仍可操作 | 当前会话退出只断开该会话；全部退出断开全部连接；指令执行时重新核对会话 | 单会话与全部会话在线撤销、其他会话保留 |
| R6 HTTP 修改回滚前旧对象 | 账号绑定、退出和管理操作在队列内重新查找玩家；密码派生在队列外，提交再次核对凭据 | 前一操作失败后排队的真实管理路由修改恢复后的对象 |
| R7 普通矿山创始人获得全服数值权限 | 生产只接受显式配置的审核员，未配置时禁用；旧创始人和存档审核员字段不授权 | 未授权拒绝、显式审核员允许、既有完整数值治理回归 |
| R8 每次操作复制全部玩家及同步开销 | 按访问的玩家根复制和校验；筛选有任务或符合条件的玩家；合并广播并共享全服矿山统计；限制排行榜传输；限制队列和数据库等待 | 1000 名存档玩家参与者数量断言、榜外真实名次、25 连接负载 |
| R9 读探针掩盖写失败 | 实际写失败保持不就绪，读取成功不能清除；实际保存成功后恢复；就绪指标同步更新 | 写失败、读成功仍不就绪、写恢复后就绪 |
| R10 CI 依赖本地存档及漏测 | 集成测试生成独立数据；真实连接测试使用独立数据库 schema；故障、容量与数值治理回归纳入发布门禁 | 从空数据库运行完整 PostgreSQL 发布检查 |
| R11 依赖漏洞 | 锁文件中的 proxy-addr 升级至 2.0.8 | 依赖审计报告 0 项漏洞 |

## 测试结果

`npm run predeploy:check` 通过，包含依赖审计、83 个基础测试命令以及 15 个服务端发布测试命令。基础测试中的矿山与长期运行测试进一步展开多个场景。结构质量门禁通过，模块行数预算未提高。

`TEST_DATABASE_URL=… npm run predeploy:postgres` 在独立的 PostgreSQL 17.10 测试实例通过，包含四个迁移、检查点、增量重放、投影、请求编号范围与淘汰重用、失败写入隔离，以及真实账号和负载连接。测试实例位于临时目录，不连接项目的正式数据库。

| 场景 | 修复前 | 修复后 | 范围 |
| --- | --- | --- | --- |
| 1000 名存档玩家，单人改名平均耗时 | 约 536ms | 约 0.8ms | 只计算服务端复制、校验和差量生成；不含数据库、网络 |
| 25 个连接，关闭持久化，操作 P95 | 约 467ms | 约 75ms | 本地生产模式；与审查测试相同的连接数量 |
| 25 个连接，真实 PostgreSQL，操作 P95 | 未取得同条件基线 | 约 305ms | 本地生产模式，数据库提交包含在操作中 |

容量结果用于证明本次瓶颈修复，不等于 1000 人同时在线承诺。世界集合仍会复制，公开排行榜仍需扫描和排序；完整检查点仍为全世界操作。正式容量应使用实际库存规模、在线人数和指令频率验证，再决定是否分区。

## 变更入口

- `server/services/durable-mutation-coordinator.js`：提交队列、读取与检查点边界、排队会话验证。
- `server/persistence/mutation-scope.js`：参与玩家根跟踪及回滚。
- `server/services/player-session-service.js`、`server/services/account-service.js`、`server/gateway/account-routes.js`：身份和账号提交。
- `server/persistence/migrations/004_request_journal_scope.sql`：恢复日志和审计请求范围修正。
- `server/services/snapshot-service.js`、`server/shell/broadcast-scheduler.js`：广播合并和排行榜传输。
- `scripts/server-architecture-regressions.mjs`、`scripts/server-capacity-regressions.mjs`、`scripts/postgres-integration.mjs`：本次主要回归。

架构说明、运营手册和生产环境模板已同步更新。修改保留在当前工作区，未提交 Git、未部署，也没有修改真实游戏存档；原有未提交的其他工作保留。

## 升级要求

上线前备份数据库，启动修复版时自动执行迁移 004。该迁移不删除已有快照和日志，但旧版应用的写入语句依赖已移除的唯一索引，不能单独回退应用代码；回退需要配套数据库备份或兼容版本。

生产环境的 `JADE_MINING_TUNING_REVIEWER_IDS` 留空时禁止正式数值审核，需要开放时填写受信任玩家编号。没有有效凭据的旧游客不会再按公开编号恢复；绑定账号可使用密码登录，无凭据游客需运营核实处理。
