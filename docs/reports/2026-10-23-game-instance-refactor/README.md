领域服务通过本实例的成就结算／领取回调调用本实例钱包，覆盖玩家归一化、任务、订单、工坊完工、直播、旧切割结算、Socket 与成就命令。旧 `bind*` 接口保留；只有兼容入口显式开启 `legacyBindings`，新实例不依赖其可变绑定。

HTTP 请求限流器和登录限流器显式持有各自的默认 `MemoryStore`，在关闭时调用 `shutdown()` 清除定时器；窗口、额度、响应及校验规则不变。Socket.IO 自身连接和资源也在关闭时释放。

## 创建与关闭契约

```js
import { createGame } from "./server/create-game.js";

const game = createGame({
  env: process.env,
  cwd: process.cwd()
  // 可选：world、createPersister；兼容入口才需要 legacyBindings: true
});
await game.startServer();
// 自定义宿主负责自己的退出策略。
await game.shutdown("host-stop");
```

`startServer()` 在 HTTP 监听成功后完成；并发／重复启动共用一个 Promise，不重复恢复存档、注册定时器或启动自动保存。`shutdown()` 也共用一个 Promise。已关闭或启动失败的实例不可重新启动，应创建新实例；新实例可用原路径恢复保存的数据。

未启动就关闭不会写入尚未读取的存档。加载、补算或监听失败时会清理已创建的资源，保留原存档；清理某一项失败仍会尝试释放其余资源。关闭发生在启动过程中时，不会在稍后又打开监听器或自动保存。

多实例使用独立 WorldStore、配置、端口和存档路径／数据库。业务定时任务仍走原有单实例耐久队列，频率、调用顺序、补算范围和玩法随机调用保持原实现。本批没有引入跨进程并行写入或修改任何保存字段。
