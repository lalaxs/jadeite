# 手镯独立精修

手镯精加工固定产出手镯，界面仅保留精修档次和抛光效果。移除手镯的成品类型下拉、镶法、金属、配石、底托、编绳与隐藏配件开关。蛋面和挂件继续使用现有镶嵌流程。

| 精修档次 | 耗时倍率 | 工艺分倍率 | 方案增值 / 封顶 |
| --- | --- | --- | --- |
| 基础出光 | 0.75 | 0.90 | 原坯估值的3% / 700 |
| 标准精修（默认） | 1 | 1 | 原坯估值的5.5% / 1000 |
| 匠心精修 | 1.5 | 1.06 | 原坯估值的7% / 1200 |

抛光可选亮光、柔光，光泽风格不直接改变估值。手镯精加工分数采用打磨60%＋修形40%，经验也计入打磨、修形。延续免费加工、设备损耗和加工失败退回原坯的规则。开工时显示当前师傅和设备对应的耗时、工艺、估值、估值变化和风险。

服务端独立校验精修方案，拒绝手镯使用镶嵌配件。客户端提交的圈口、玉料底稿、报价等字段不会替换服务端原件。精修保留真实玉件的圈口、轮廓、颜色、飘花、棉裂和来源；手镯孔洞保持透明。

成品保存独立的`finish`记录和单一玉件组件。锦匣、库存卡片、库存详情、订单、交易行、收藏和黑市共用工艺摘要，旧手镯根据来源显示为手镯并保留历史光泽。旧在途任务沿用历史报价结算，兼容仅记录倍率的早期任务。

手镯订单使用工艺和光泽条件，生成和补单时会转换旧镶法、金属条件；匹配计算也兼容旧条件。已移除珠串/珠链的产品分类、套件、默认位置、订单候选、渲染及印章的遗留识别；现有11种玉件题材保留。

## 验证

`npm run test:bangle-finish`覆盖6种组合的真实开工、结算和领取，前后报价一致、耗时与工艺差异、无外部材料消耗、失败回滚、玉料一致性、公开快照和JSON恢复、历史任务，以及手镯订单的匹配和250次订单生成。已纳入`npm test`。

完整回归共111项全部通过，结果见`checks.json`、`summary.json`；30天模拟经营及SQLite多次重启恢复首次触及批量执行器180秒时限，单独放宽时限重跑后通过，原始尝试保留在记录中。收尾改动后再次通过相关加工、订单、库存、交易、纹理与界面检查。

浏览器记录见`browser-checks.json`。浏览器运行在独立3014端口、`JADE_WORLD_PERSIST=0`的测试世界，未修改实际玩家存档。实测桌面1280×720和手机390×844；从选择毛坯、精修、锦匣领取到库存详情、订单匹配与交易行实际挂牌。手机无横向溢出，开工按钮可见，浏览器无警告和错误。
