# 翡翠街服务端架构

## 目标

首个公开版本采用单区、单权威游戏进程。浏览器只提交指令和显示结果；现金、库存、随机结果、生产时间、交易与托管均由服务端决定。PostgreSQL 是耐久状态边界，Socket.IO 是实时传输层，不是状态来源。

## 运行拓扑

```text
Browser -- HTTPS/WSS --> Caddy --> Node.js + Socket.IO --> PostgreSQL
                                      |                    |
                                      +-- health/metrics   +-- snapshots
                                      +-- command barrier  +-- audit log
                                      +-- due-job ticks    +-- projections
```

第一版只允许一个 Node.js 游戏进程。当前全服模拟状态驻留在该进程内，多副本会产生两个互相冲突的权威世界。容量扩展先依据实测决定是否拆分独立世界或分区，不能直接增加同一世界的游戏进程副本。

## 指令提交边界

客户端写操作都携带 `requestId`。服务端按以下顺序处理：

1. 校验来源、频率、消息大小和结构。
2. 根据会话确定玩家，不接受客户端指定资产所有者。
3. 串行执行权威领域服务。
4. 生成本次操作的世界差量及受影响玩家的查询投影。
5. 在 PostgreSQL 事务中写入差量日志、流水投影、幂等键和审计记录。
6. 事务提交后才发送状态、提示或确认回包。
7. 保存失败时恢复修改前世界，丢弃尚未发送的网络效果。

因此客户端收到成功状态时，该操作已经进入耐久存储。

游戏操作、状态读取、HTTP 账号与管理操作、自动检查点及手动检查点共用调度队列。读取与检查点等待前面的提交完成；断开连接立即移除传输绑定，离线时间随后进入队列保存，回滚不恢复已断开的连接。账号与管理操作在实际执行时重新取得玩家对象，避免引用回滚前的旧对象。

普通操作按访问的玩家根复制前后状态，同时复制世界集合；交易双方都进入同一回滚范围。完整检查点保留全世界校验。玩法服务应在队列内通过 `WorldStore` 或 `state.players` 取得玩家，不能捕获队列外的可变玩家对象；`playersMatching` 的筛选条件必须只读。定时任务先筛选有任务或符合条件的玩家，再进行标准化和结算。

队列最多接受 256 个运行中或等待中的任务，等待超过 10 秒的任务返回 `SERVER_BUSY`；同一种周期任务不重复排队。数据库查询超时为 5 秒、锁等待超时为 2 秒。密码派生在队列外执行，提交时再次核对身份、登录名占用及凭据版本。

矿山完整健康巡检在启动时执行一次，运行期间每 15 秒通过同一队列的只读入口执行；它不创建回滚范围、不写数据库。生产、矿山班次、租期和托管的到期结算仍保持每秒执行。25 秒工坊刷新只访问在线玩家；离线任务由到期结算和上线补算处理。

矿山资格、名单和未变化的租约检查采用只读访问，不把已有合格玩家的整个库存纳入回滚复制。发放或修复许可证、补矿工、租约历史同步和退还冻结资金仍通过可写访问取得玩家。只读访问返回的对象不能修改；实际写入前必须通过 `get` 或 `playersMatching` 重新取得根。

## 持久化模型

`jade_world_snapshots` 是周期性完整权威世界检查点，保留最近多个可校验版本；`jade_world_mutations` 是每次已提交指令的增量日志。启动时从最近可用检查点按序重放差量；检查点或差量均有 SHA-256 校验，最新检查点损坏时自动尝试上一版本。普通玩家操作不再重写整个世界快照。

以下表是同事务更新的运维与查询投影：

- `jade_player_projection`：玩家关键经营指标。
- `jade_ledger_entries`：不可重复插入的资金流水。
- `jade_idempotency_keys`：重启后仍有效且与玩家有界请求历史一致的去重记录。
- `jade_inventory_projection`：当前直接持有库存的所有权投影。
- `jade_audit_log`：玩家指令和管理操作审计。

玩家摘要只在对应字段变化时更新。直接库存按物品编号对比所有者、位置、类型和内容，只删除移出的条目、更新变化的条目；所有参与者的删除先于新增，物品转移不依赖玩家遍历顺序。请求记录只新增本次编号、删除被淘汰编号，流水仍按编号追加。改名不会重写库存。

恢复时只复制一次检查点、建立一次玩家索引，再按序应用日志中的变化根。每条日志的校验值、版本和时间仍逐条核验，完整恢复结果经世界校验后才导入；失败不会把部分重放结果暴露给玩法。

数据库迁移按编号和校验值执行，并由 PostgreSQL advisory lock 串行保护。审计日志默认保留 90 天，可通过 `JADE_AUDIT_RETENTION_DAYS` 在 7–3650 天内调整。

请求去重范围是每名玩家最近 200 个编号，跨事件共用该玩家的编号历史；其他玩家可以使用相同编号，编号淘汰后再使用按新操作处理。迁移 004 移除日志和审计表原有的全服请求编号唯一索引，日志每次记录实际提交的变更，不能因请求编号冲突静默跳过写入。

完整检查点仍是恢复来源，投影不能反向覆盖世界。这样可在不一次性重写全部玩法服务的前提下获得事务恢复、查账和后续关系型迁移路径。

## 身份与账号

- 新玩家先获得高熵游客恢复令牌。
- 服务端只保存令牌哈希，不保存原始令牌。
- 每名玩家最多保留有限数量的有效会话，会话会过期、可单独撤销或全部撤销。
- 验证会话是只读操作；公开玩家编号不能认领没有有效凭据的角色，包括过期和已撤销的账号。旧版有效哈希令牌验证后可轮换为新会话。
- 退出当前会话只断开该会话的连接；退出全部会话断开该玩家所有连接。排队中的指令在执行时重新检查会话有效性。
- 玩家可绑定独立登录名和密码；密码使用带随机盐的 scrypt 派生值。
- 正式账号登录写入 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- 登录接口使用独立的 15 分钟频率限制，不存在的用户名也执行同样的 scrypt 计算，减少账号枚举信号。
- Socket 握手优先兼容现有本地游客令牌，同时支持安全 Cookie。

## 实时同步

支持 `statePatchV1` 的客户端首次连接接收完整状态，之后只接收发生变化的顶层状态片段。每个补丁包含 `baseVersion` 和 `stateVersion`；版本断裂时客户端请求完整重同步。旧客户端继续接收原有完整 `state`，便于平滑迁移。

同一事务内重复触发的广播合并为一次，多个已提交操作的广播再按 25 毫秒窗口合并，并保留所有受影响玩家的私有片段。实际广播在读取队列内生成，所有连接复用公开快照和矿山全服统计。客户端渲染管线依据变更键只更新相关页面。

公共快照的字段签名在每轮广播中只计算一次，个人片段仍独立计算。排行榜根据实际公开玩家资料的指纹复用排序与名次索引；昵称、分数、收藏或玩家增删会更新，聊天变化不会重新排序。缓存保留一版，传输对象与缓存对象隔离；回滚或直接修改后的实际状态也会使指纹更新。

首次同步、缓存重置后的同步和旧客户端的完整状态始终包含个人资料与静态目录。即使新连接先碰到一条与自己无关的公共广播，也不能把省略个人资料的片段当作完整状态发送。

公开玩家目录和各排行榜最多发送 100 名；玩家榜外的真实名次及上一名另外发送，市场卖家的声望、等级通过 `marketPlayers` 提供。排行榜不会把全部存档玩家发给每个连接。

连接会进入 `world` 和 `player:<id>` 房间，为后续公盘、市场和矿区频道拆分保留边界。

## 安全边界

- 生产环境不注册加钱、解锁、刷物品等调试事件。
- 生产环境只有 `JADE_MINING_TUNING_REVIEWER_IDS` 明确配置的玩家可以审核全服矿山数值；留空时关闭正式审核权限，存档中的创始人和旧审核员字段不会自动授予权限。
- 生产环境必须配置精确的 `PUBLIC_ORIGIN`。
- HTTP 和 Socket 分别限流。
- Socket 限制单包大小、嵌套深度、数组长度、字段数量和文本长度。
- 所有写事件先经过 Zod 事件信封和关键字段语义校验；拒绝带回稳定错误码并响应 ack。
- 生产写操作必须携带合法 `requestId`。
- Helmet 提供 CSP、HSTS、点击劫持和 MIME 防护。
- 日志自动遮蔽 Cookie、Authorization、密码和令牌。
- 管理接口使用独立长随机令牌，未授权请求返回 404。

## 可观测与恢复

- `/health/live`：进程存活。
- `/health/ready`：启动、存档和监听均已就绪。
- `/health/ready` 会主动探测持久化后端；数据库失败会撤销就绪，恢复后自动重新就绪。
- `/version`：发布版本。
- `/metrics`：受管理令牌保护的 Prometheus 文本指标。
- 操作队列等待、计算、耐久提交、数据库事务及广播各阶段使用累计直方图，支持按事件查询 P95/P99；检查点准备另计。指标标签不包含玩家或请求编号。
- SIGINT/SIGTERM 会停止连接、等待写入队列、保存世界、关闭数据库后退出。
- PostgreSQL 每日生成自校验自定义格式备份，并按保留天数清理。
- GitHub Actions 在 Ubuntu 24.04、Node 24 和真实 PostgreSQL 服务上执行架构门禁、完整回归及数据库集成测试。
- 真实数据库发布门槛包含持续混合玩法测试：默认 1,000 个存档玩家、25 个连接、每人 100 件成品，采购、交易、生产、矿山、去重与重连持续至少 45 秒，并核对全部直接库存与请求投影及重启恢复。测试加速生产和矿山时钟，数据使用独立 schema。
