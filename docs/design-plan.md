# 翡翠经营多人网页游戏原型方案

## 一句话定位

这是一款以翡翠行业为题材的多人网页经营游戏。玩家不被职业限制，可以在同一个服务器里自由选择“拍原石、倒卖、切石、加工、接订单、收藏、直播销售”等模块，靠判断、资金管理和声望经营赚钱。

## 第一版原型目标

第一版不追求完整商业化系统，而是验证核心循环是否成立：

1. 公盘生成原石，玩家花钱拍下。
2. 玩家可以转手卖原石，也可以切开赌涨跌。
3. 切出的料子可以加工成手镯。
4. 手镯可以卖给 NPC、放进藏宝阁收藏，或挂到玩家交易行。
5. 声望影响 NPC 订单质量和玩家排名。
6. 多个浏览器窗口连接同一个本地服务器，共享市场、战报和交易行。

## 核心模块

### 1. 行为模块

| 模块 | 核心玩法 | 第一版实现 |
| --- | --- | --- |
| 拍原石 | 公盘暗标，买下带风险的原石 | 已实现，系统定时刷新原石 |
| 卖原石 | 玩家间加价转卖 | 已实现，交易行可挂牌 |
| 切原石 | 揭开真实品质，可能暴涨或切垮 | 已实现，生成料子或废料 |
| 做手镯 | 把料子加工成成品 | 已实现，消耗料子和加工费 |
| 卖成品给玩家 | 交易行出售 | 已实现 |
| 接 NPC 定制单 | 按要求交付手镯 | 已实现，声望影响订单 |
| 直播带货 | 系统 AI 买家购买成品 | 已实现，随机成交价 |
| 收藏藏宝阁 | 收藏高货提升声望 | 已实现 |

### 2. 成品销售双轨制

玩家销售成品有两条路线：

第一条是玩家市场。手镯不是纯粹的消耗品，其他玩家可以购买并收藏，形成“撑门面”的需求。

第二条是 NPC 订单。NPC 客户有不同预算和品质要求，玩家声望越高，越容易接到高利润订单。订单满意度来自时间、品质和数量，第一版先实现品质匹配和基础满意度。

### 3. 声望系统

声望来源包括：

| 来源 | 第一版实现 |
| --- | --- |
| 切出好货 | 高品质料子会发全服战报并增加声望 |
| 收藏好货 | 收藏手镯立即增加声望 |
| 完成 NPC 订单 | 按要求交付增加金钱和声望 |
| 玩家交易 | 成交后获得少量信誉声望 |

声望用途包括：

1. 决定 NPC 订单档次。
2. 决定排行榜名次。
3. 提高直播带货成交能力。
4. 作为后续高端公盘入场门槛。

## 后续正式版建议

第一阶段：继续强化单服原型，补上账号、存档、更多订单和更细的品质维度。

第二阶段：接数据库，保存玩家资产、交易记录、收藏品、订单满意度。

第三阶段：加入房间、频道、公会、长期合同、拍卖倒计时、真实竞价。

第四阶段：部署到云服务器，支持朋友通过网址一起玩。

## 技术结构

当前原型结构：

```text
浏览器网页
  |
Socket.IO 实时通信
  |
Node.js 游戏服务器
  |
内存数据
```

正式版建议结构：

```text
浏览器网页
  |
HTTPS + WebSocket
  |
Node.js 游戏服务器
  |
PostgreSQL 数据库
  |
Redis 缓存与排行榜
```
