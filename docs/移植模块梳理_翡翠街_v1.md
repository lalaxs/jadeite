# 《翡翠街》→ TapTap 竖屏移植 · 全功能模块梳理 v1.0

> **来源项目**：`jade-market-prototype`（Node + Express + Socket.IO 多人翡翠经营网页原型）
> **目标项目**：TapTap 竖屏 H5 小游戏（离线打包、竖屏、触摸操作）
> **梳理日期**：2026-09-10
> **证据基准**：以**当前代码实现为准**。`docs/翡翠风云_GDD_v2.1.md` 为早期设计意图，与实际实现存在明显偏差（见 §7.1），移植时一律以代码为准。
> **约束前提**：不能复制源码到 TapTap 项目，只能提取业务逻辑 / 数据 / 规则；不能搬网页 DOM、鼠标事件、横屏布局。

## 0. 分类口径

本文档对每一项都打三个标签之一：

| 标签 | 含义 | 移植动作 |
| --- | --- | --- |
| 【游戏核心逻辑（移植保留）】 | 与渲染/输入无关的规则、数值、状态机、算法 | **提取逻辑原样搬运**，只换宿主（本地权威 / 新 UI） |
| 【资源素材（可复用）】 | 色板、字体、图标、SVG 生成算法、文案表 | **复制素材或算法**，重新接竖屏容器 |
| 【网页特有，移植时丢弃】 | DOM、鼠标事件、窗口适配、网页弹窗、横屏栅格、Socket.IO 传输 | **丢弃重写**，仅保留其承载的数据语义 |

一个模块可能同时含多类内容，此时在模块内分条标注。

## 2. 全局底层约定（先读这节，否则单模块会读歪）

### 2.1 权威模型

- 世界状态唯一持有者：`world-store.js` 的 `createMemoryWorldStore()` 返回值 `world`，可变袋子为 `world.raw`（`server.js` 里 `const state = world.raw`）。
- 顶层容器：`players(Map)`、`sockets(Map)`、`roughPool`、`listings`、`blackListings`、`blackStalls`、`blackServiceOrders`、`wants`、`news`、`auction`、`latestAuctionResults`、`auctionHistory`。
- **重要：目前是纯内存态，无任何写盘调用。** `exportSnapshot()/importSnapshot()` 已备好 JSON 信封但无人调用。
- **移植必改**：单机竖屏版没有常驻服务器，必须把"服务器权威"降级为"本地权威 + 本地持久化"。

### 2.2 调用约定

| 约定 | 内容 |
| --- | --- |
| 幂等 | 所有会改状态的请求带 `requestId`，服务端 `consumeRequestId` 去重，重复返回提示 |
| 货币 | `money()` 取整且非负；`uiMoney()` 显示为 `¥1,000`（符号 ¥，文中称"翠币"） |
| 押金 | `holdDeposit`/`releaseDeposit` 记流水但 `repEligible:false`（押金不涨声望） |
| 声望联动 | `recordLedger` → `repFromCashFlow` = `floor(amount/10000)×10` |
| 分离 | 服务端只做规则与状态；前端只做表现与意图提交 |

### 2.3 时间与心跳（当前实现，非 GDD）

| 心跳 | 周期 | 职责 |
| --- | --- | --- |
| 慢心跳 | **25000ms** | 打磨/生产结算、公盘刷新、拍卖推进、求购过期、黑市服务单过期与状态刷新、盲盒过期、空摊清扫、在线玩家订单日刷新、**声望自然衰减 −0.35（下限 5）**、广播 |
| 快心跳 | **1000ms** | 生产 Job 推进、直播间推进、拍卖推进、求购/黑市/盲盒过期，**有变更才广播** |
| 材料价格 ticker | **60000ms** | 追加材料价格历史 |
| 启动一次性 | — | 开价格 ticker、刷新原石池、发"开市"新闻 |

### 2.4 一级/二级状态字段速查

- 玩家：`cash / rep / exp / level / achievementPoints / satisfaction / assets / rough / materials / slices / bracelets / collection / jobs / livestreamJobs / livestreamRoom / orders / payouts / blackPayouts / ledger / repHistory / expHistory / ratingHistory / reports / offlineSummary / pendingBmRatings / stats{...}`
- 物品阶段：`materialStage ∈ { rough, opened, carved, polished, finished }`

## 3. 模块详情

### M01 原石池与公盘竞拍

**分类**：【游戏核心逻辑（移植保留）】＋ 多人部分需替换为 AI
**承载**：`server/services/rough-pool-service.js`、`server/services/auction-service.js`、`public/jade-auction.js`

**模块作用**：源源不断生成带风险的原石（品质/雾壳/视觉伪随机），并通过 5 档公盘暗标把原石投放到玩家手里。

**内部子功能**
- 原石生成：品质加权抽样、专家线索文本、视觉参数（雾壳/蟒带/裂纹角度）
- 原石池维持：池目标数补充
- 公盘生命周期：开厅 → 入场收保证金 → 暗标出价（可改）→ 到点统一开标 → 结算报告投递
- 抵押托管：差额冻结、落标退还、陈旧押金退还
- 开窗：付费揭示局部真实信息
- AI 补标：出价人数不足时补位

**关键数据结构**
```
原石 { id, name, publicHint, hint, mass, price, trueValue, deposit, risk,
       expertClues[], windows[], trueQualityKey, materialStage,
       visual{ seed, skin, vein, window, crack, belt, beltAngle, crackAngle,
               bestAngle, suggestedAngle, shape, grain, translucency,
               cotton, speckles, skinRoughness } }
QUALITIES[] { key, name, score, color, rep, value }
公盘 auction { id, hallId, hallLabel, status, startsAt, endsAt, biddingEndsAt,
               entryFee, entries[], roughs[], bids[], results[] }
投标 bid { playerId, roughId, amount, at, ai }
结果 result { roughId, winnerId, price, ai }
玩家押金 player.auctionEscrow[] { roughId, roundId, amount, at }
```

**触发条件**
- 客户端：`enterAuction` / `joinAuction`、`submitAuctionBid`、`requestWindow`、`ackAuctionSettle`
- 心跳：`processAuctionLifecycle`（1s / 25s）、`refreshRoughPool`

**游戏规则与数值**（已交叉验证源码）
| 厅 | 等级门槛 | 开窗费率 | 入场费/保证金 |
| --- | --- | --- | --- |
| novice 新手公盘 | Lv.1 | 6% | ¥5,000 |
| regular 常规公盘 | Lv.2 | 7% | ¥8,000 |
| premium 精品公盘 | Lv.3 | 8% | ¥16,000 |
| special 专场公盘 | Lv.4 | 9% | ¥30,000 |
| legendary 传奇公盘 | Lv.5 | 10% | ¥60,000 |

- 单场时长 **10 分钟**、每场 **8 块原石**；截止前 **10 秒**停止入场（已付费可进）
- 暗标约束：`bidAmount >= rough.price`（不得低于保底价，低于则流拍）
- 开窗费 = `rough.price × windowRate`，每块原石**仅 1 次**
- AI：每块原石最多 **3 标**，出价区间 `ratio = 0.6 + (seed%36)/100`
- 开标：按金额降序、同价先出者得；按差额 `delta` 冻结押金，落标全额退还
- 拍卖历史保留 **24 场**
- 品质概率：豆种 40% / 糯种 24% / 糯冰 16% / 正冰 10% / 高冰 7% / 玻璃种 3%
- 种水六档（高→低）：玻璃种＞高冰＞正冰＞糯冰＞糯种＞豆种；**帝王绿是色不是种**
- 原石公式：`basePrice = 900 + score²×720 + mass×620`；`price = basePrice×(0.68~1.56)`；`trueValue = price×(1.78 + score×0.04)`；`deposit = basePrice×0.18`
- 池常量：`STARTER_ROUGH_COUNT=3`、`ROUGH_POOL_TARGET=8`
- 六种雾壳：白雾 / 黄雾 / 黑乌砂 / 脱沙 / 松花 / 蟒带

**移植注意**：暗标的"赌性"依赖**信息不对称**。单机版没有真实对手，AI 补标必须保留"出价不可见"语义，否则赌性消失。

### M02 开料/切石引擎

**分类**：【游戏核心逻辑（移植保留）】＋ SVG 渲染层需替换
**承载**：`public/jade-opening-engine.js`（49KB，核心资产）、`public/jade-volume.js`

**模块作用**：用噪声网格模拟原石内部结构，按玩家选择的切面/套件位置计算露出什么料、值多少钱。

**内部子功能**
- `buildJadeMap`：建 40×40 网格（`CELL=15`），fbm 噪声划分废料区 / 色区 / 裂纹
- `jadeCracks`：按 roll 生成 0~7 条裂纹
- `buildOpeningStone`：生成品类数、花/色标记
- `evaluateOpeningKit` / `evaluateWholeStone`：按套件几何命中统计网格求价
- `computeGrade`：品质分 → 14 档评级
- `defectPenalty`：裂纹/废料惩罚合成
- `renderJadeOpeningSvg`：**SVG 字符串生成（网页渲染，需替换为 Canvas 2D）**
- `jade-volume.js`：3D 体积采样（棉絮/绿色脉）

**关键数据结构**
```
网格元 { cat, waste, crack }
评价 { total, goodN, wasteCount, crackCount, catCounts, avgRar, avgCv,
       crackRatio, wasteRatio, penalty, price, priceMul }
余料 { coverage, remainRatio }
PALETTES：38 色卡（帝王绿 rarity6 / w0.5，油青 rarity3 / w8）
GRADES：6 档种水（玻璃种＞高冰＞正冰＞糯冰＞糯种＞豆种；帝王绿在 PALETTES 色卡，不是种）
KIT_LIB：7 套件（egg r34 mul0.65 / bangle r88 mul1.85 / buddha r110 mul1.15 …）
```

**触发条件**：被 `workshop-service` 的开工与产出链路调用；切面选择由前端交互提交

**游戏规则与数值**
- 废料：`freq 0.009` 的 `smoothstep(0.56,0.76) > 0.5`；色区：`freq 0.0042` 的 `smoothstep(0.42,0.70)`；裂纹：`distToPoly < 6`
- 裂纹条数：`roll<0.25→0`、`<0.6→1`、`<0.85→2+rand2`、否则 `4+rand3`；长度 `110 + rng×280`
- 求价：`price = goodN × 55 × valueFactor × (1−penalty) × priceMul`
- `valueFactor = 0.10 + c×0.62 + q×0.38 + c×q×0.55`
- 余料价值 ×0.72
- 缺陷惩罚：裂 `cr>0.02 → min(0.70, 0.15+cr×1.2)`；废 `wr>0.10 → min(0.55, 0.10+wr×0.6)`；合成 `1−(1−a)(1−b)`
- 品质分 = 色(`avgRar/6×40`) + 水(`water×30`) + 完整(`(1−wr−cr)×20`) + 纯净(`(1−penalty)×10`) → `GRADE_TIERS` 14 档（S+ ≥95 … F 0）
- 校验基线（测试断言）：`jadeMap` 40×40 = **1600 格**；套件 **7 种**；bangle 倍率 **1.85**；`jadeValueFactor(6,1)×100 = 165`；S+~F 共 **14 档**

**移植注意**：模拟核心（网格/fbm/命中/评分公式）是纯函数，可原样搬运；`renderJadeOpeningSvg` 产出的 SVG 字符串不能直接用于 H5，需改 Canvas 2D 绘制（字段 `visual.*` 全部可复用）。

### M03 工坊三阶段加工

**分类**：【游戏核心逻辑（移植保留）】
**承载**：`server/services/workshop-service.js`、`workshop-roster.js`

**模块作用**：编排"开料 rough → 取件 refine → 精加工 inlay"三阶段流水线，管设备/师傅匹配、计费、耐久、碎裂与结算。

**内部子功能**：设备与师傅解析、排料重叠校验、开工排程、完工结算、工分聚合、余料回收、委托标记继承

**关键数据结构**
```
设备 { id, stage: opening|carving|finishing, inputType, inputStage, outputStage,
       durationStage, attrs:{ speed, quality, risk, perfectFloor },
       workerId, condition, needsKits, capacity:1 }
师傅 { id, name, job, tier, tierLevel, baseWage, traits, flaws,
       skills:{ cut, set, finish, speak } }
Job  { id, type:"productionJob", stage, deviceId, deviceAttrs, workerId,
       outputStage, outputPreview, item, options, fee, startedAt, readyAt,
       finishPlan?, inlayQuote?, reservedMaterials?, durabilityApplied?,
       craftScores?, craftWorkers?, deviceQualityBonuses?, craftScore?,
       craftGrade?, baseValue }
```

**触发条件**
- 客户端：`startWorkshopJob`、`assignWorkshopWorker`
- 心跳：`processProductionJobs`（1s）

**游戏规则与数值**
| 阶段 | stage | 输入桶 | 输入阶段 | 产出 | 人工费 | 需套件 |
| --- | --- | --- | --- | --- | --- | --- |
| 开料 | opening | rough ∪ materials | rough | material（materialStage=opened） | ¥620 | 否 |
| 取件 | carving | materials | opened | bracelet（stage=carved）+ 余料回库 | ¥900 | 是 |
| 精加工 | finishing | bracelets | carved | bracelet（stage=finished） | ¥680 | 否 |

- **容量恒为 1**，同一设备不排队；设备在忙则直接拒绝（`jobsForDevice >= 1` 即拒）
- 师傅忙则拒绝（跨工坊/直播统一判定）
- 耗时缩放：`wsSpeedTimeScale(worker) × max(0.2, 1 − min(0.8, device.attrs.speed/100))`
- 碎裂：仅当 `device.attrs.risk > 1` 触发，基础概率 `(risk−1)×0.08`，叠加 `employeeShatterDefense(worker)`，上限 0.95
- 碎裂后果：开料/取件物料全损；精加工退回翡翠**与镶嵌材料**，人工费不退还
- 成品价值：`price = baseValue × (1 + overall/100×PROCESS_BONUS_CAP + Σ设备品质加成%) × gradeMult`，`PROCESS_BONUS_CAP = 0.3`
- 镶嵌成品无方案时 `valueMultiplier = 1.2096`，有方案时为 1.0（方案已内含加成）
- 帝王绿触发 `stats.everImperial = true`
- 耐久：完工时 `durabilityLoss(device)`，clamp 0~100
- 初始工坊：**3 台设备**（opening/carving/finishing 各 1）+ **4 名师傅** + **3 名招聘候选**

### M04 片料规划与落位判定

**分类**：【游戏核心逻辑（移植保留）】
**承载**：`server/services/workshop-planning.js`、`public/jade-rules.js`、`public/product-meta.js`

**模块作用**：把"在切片画板上把套件摆在哪、转多少度、多大"翻译成成品价值——这是全游戏**唯一的空间交互判定**。

**内部子功能**：套件归一化、椭圆足迹、重叠检测、色带/裂纹/开窗命中评分、明料揭示定价

**关键数据结构**
```
套件 kit { id, type, openingTpl, x∈[4,96], y∈[4,96], rot∈[0,180),
           scale∈[0.45,1.45], size:"S"|"M"|"L", ringSize∈[52,62] }
placement { id, layout, x∈[12,88], y∈[12,88], ringSize(偶数 52~62), radius,
            kitId, kitType, openingTpl, rot, scale, size, templateLabel, templateSize:{w,h} }
切片画板 { outlinePath, flaws, colorZones, baseColor, groundColor,
           grainAngle, cleanScore, clarity, water∈[0.16,0.96],
           dirtySpots, cottonThreads }
套件→成品映射 OPENING_KIT_SERVER_TYPES：
  egg→cabochon / ping→peacePendant / rect→plaque / drop→dropPendant
  leaf→leafPendant / bangle→bangle / buddha→buddhaPendant
```

**触发条件**：由 `startWorkshopJobForPlayer`、`extractProductsFromJob`、内部 `priceByCraft` 链式调用；落位坐标由前端拖拽产生

**游戏规则与数值**
- 画板基准 `KIT_BOARD_REFERENCE = { width: 412, height: 148 }`；板上最多 **10 套件**，单套件 8 slot
- 粗料评分 `scoreRoughPlacement`：基础 0.82 ＋彩带命中 +0.18 ／ 开窗命中 +0.08 ／ 圈口 ≥58 +0.05 ／ 小件 +0.05 − 出框每边 −0.22 − 裂纹 −0.18，clamp **[0.5, 1.22]**
- 切片评分 `scoreSlicePlacement`：基础 0.82 ＋彩带 +0.18 ＋大圈 +0.06 − 边缘 −0.18 − 瑕疵 −0.24 − plaque −0.04，clamp **[0.48, 1.24]**
- 命中距离：色块中心与 placement 距离 **< 22** 算吃色；裂纹距离 **< radius+3** 算压裂
- 旋转：`normalizeAngle = ((v%180)+180)%180`，最小角距 `min(diff, 180−diff)`
- 重叠：套件层 `computeOverlaps`；placement 层椭圆近似 `(dx/rx)² + (dy/ry)² < 1`
- 揭示定价 `revealPolishedRough`：`money(rough.price × quality.value × (0.88 + rand×0.34))`
- 成品取值：`valueBase = max(rough.value, rough.price)/(totalSlots+1) × productMeta.mult × placementScore`
- 声望：`rep = (rough.rep×productMeta.rep×0.35 + rough.score×2 + openingGrade.score×0.08) × clamp(placementScore, 0.72, 1.18)`
- `jade-rules.js` 另有 `analyzeRoughPlacement`（基础 82 分制）与 `evaluateOrderFit`（订单匹配度），服务于订单/求购判定

**移植注意**：**这是全项目交互改造量最大的一块**。网页版用 `pointerdown/move/up` + `getBoundingClientRect` 换算百分比坐标（`main.js:2619-2657`），该范式可直接照搬到触摸，但画板尺寸 412×148 为横屏比例，竖屏必须重排（建议改竖版画板或允许缩放平移）。
