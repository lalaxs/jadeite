# 翡翠经营模拟：优先级 1～5 优化设计

> 日期：2026-07-24
>
> 状态：用户已逐节确认
>
> 适用项目：`jade-market-prototype`
>
> 实施顺序：测试基线 → 工作区整理 → 桌面端布局修复 → 移动端适配 → 设备/员工/镶嵌闭环

## 1. 背景

项目已经具备可玩的多人经营原型：公盘竞拍、开料、规划、精加工、藏品、订单、市场、商铺、直播、排行榜等主流程均已出现。当前主要问题不是缺少页面，而是工程基线和几个核心闭环尚未收口：

- 两条冒烟测试仍断言旧流程，导致测试套件不是全绿。
- 工作区存在大量删除、修改、未跟踪文件及备份、日志，不能直接清理或整体重置。
- 桌面端低高度下存在聊天遮挡、滚动位置延续、工坊第三列被右侧栏覆盖等问题。
- 手机宽度下仍保持桌面宽布局，核心内容无法完整操作。
- 设备已有属性和展示，但购买、耐久与维修未闭环。
- 员工已有技能模型和四名初始员工，但招聘、经验增长与升级未闭环。
- 商铺已有镶嵌材料目录和库存，但精加工尚未真正选择、消耗并记录镶嵌方案。

本设计先稳定现状，再补三个最小完整经营闭环，不扩展为完整商业版本。

## 2. 目标与硬约束

### 2.1 本轮目标

1. 修复过时测试，让 `npm test` 一次运行全部通过。
2. 对当前工作区做证据驱动的安全整理，形成可继续开发的基线。
3. 修复桌面端遮挡和溢出问题，同时保持桌面端 UI 排版不变。
4. 让 390×844 与 430×932 两种手机尺寸能够完成核心经营流程。
5. 完成设备、员工、精加工镶嵌三个最小闭环。

### 2.2 硬约束

- 桌面端顶部资源栏、左侧导航、中间内容区、右侧事务栏和底部聊天的顺序、位置、视觉风格不变。
- 桌面端不重新设计配色、字体、卡片风格、全局导航或三栏结构。
- 每台设备的 `capacity` 永久且只能为 `1`。
- 每台设备最多一个进行中任务，不存在等待生产队列。
- 同工序可以拥有多台设备；每台设备是独立生产线。
- 所有经济、资源、设备、员工占用和完工结算由服务端判定。
- 本轮继续使用内存状态，不引入账号、数据库、云存档或部署系统。
- 不使用整体重置、强制清理等方式覆盖当前工作区中的用户改动。

### 2.3 明确不做

- 玩家设备交易、设备出售、拆解、升级和随机故障。
- 黑市设备与高阶设备获取；本轮商店只售现有九种 1 阶型号。
- 员工解雇、员工交易、品阶晋升资源、特质重洗。
- 新增或重做材料价格波动；材料采购沿用当前商铺目录与现有价格逻辑。
- 镶嵌材料拆解回收、订单材料奖励和黑市材料采购。
- 独立移动版页面或另一套移动端 DOM。
- 与本轮目标无关的大规模重构。

## 3. 方案选择与实施原则

采用“稳定优先”方案：

1. 先修测试，得到可信的失败/成功信号。
2. 再整理工作区，避免后续提交混入历史残留或误删文件。
3. 修复桌面端布局，建立不可破坏的桌面基准。
4. 在同一 DOM 上增加移动端响应式规则。
5. 依次完成设备、员工、镶嵌闭环。
6. 最后执行完整测试与双端浏览器回归。

每个阶段先写会失败的测试或可复现检查，再做最小修改使其通过；每个阶段单独验证并单独提交，便于回退和审查。

## 4. 架构与模块边界

保留现有原生 HTML/CSS/JavaScript、Express 和 Socket.IO 技术栈。`server.js` 继续负责连接、事件编排、广播及现有主循环；新增或改动的领域规则放入三个聚焦模块：

- `server/systems/equipment-system.js`
  - 设备目录、购买、容量校验、耐久损耗、禁用和维修。
- `server/systems/employee-system.js`
  - 候选人生成、刷新、招聘、员工占用、经验与升级。
- `server/systems/inlay-system.js`
  - 成品/镶法/材质兼容、成本预估、库存消耗、失败返还和价值计算。

模块只处理规则和数据，不直接操作 DOM，也不直接广播 Socket.IO。`server.js` 调用模块，成功后统一记录流水、新闻和状态广播；失败时统一返回错误结果。

客户端继续使用现有模块：

- `public/main.js`：视图切换、全局事件和中央滚动管理。
- `public/workshop-module.js`：设备、员工选择、精加工配置和进度展示。
- `public/extra-module.js`：商铺设备货架、招聘和材料入口。
- `public/market-module.js`、`public/orders-module.js` 及藏品展示：显示镶嵌元数据。
- `public/styles.css`：桌面端约束修复与移动端媒体规则。

客户端只提交“玩家意图”，不自行决定余额、库存、任务占用、经验、耐久或成品价值。

## 6. 阶段二：工作区安全整理

### 6.1 审计规则

对每个删除项和未跟踪项检查：

1. 是否被 HTML、JavaScript、CSS、脚本或文档引用。
2. 是否有明确替代文件，且替代文件已包含等价内容。
3. 是否是生成物；如果是，生成脚本和输出约定是否仍有效。
4. 是否是备份、日志、测试临时文件或一次性报告。
5. 是否承载历史设计决策，且没有等价归档。

处理结果分为：

- **保留删除**：有明确替代或确认无引用。
- **恢复**：仍被引用、用途不明或没有等价归档。
- **纳入版本控制**：当前运行必需的新模块、脚本和资源。
- **忽略**：`.bak`、运行日志和明确的临时产物。

### 6.2 安全边界

- 不运行会批量删除未跟踪文件的命令。
- 不整体回退当前分支。
- 不覆盖与本轮目标无关的用户修改。
- 无法判断的文件默认恢复或保留，等取得证据后再处理。
- 整理后输出实际“保留、恢复、删除、忽略”清单。

### 6.3 基线提交

整理后依次执行：

1. 全量测试。
2. 桌面端核心流程冒烟。
3. 检查页面资源请求和控制台错误。
4. 仅在上述检查通过后形成安全基线提交。

- 切换主视图时只重置中央内容滚动位置，不改变页面其他滚动状态。
- 1280×720 等低高度桌面使用区域内部滚动，不把桌面三栏改成上下排列。
- 弹窗限制在视口内并允许内部滚动。

### 7.3 桌面验收

- 在 1280×720 和常用更高分辨率保存改动前后截图。
- 外层区域的顺序、左右位置和视觉风格不发生非必要变化。
- 聊天不遮挡主操作。

- 视图切换后中央内容从顶部开始。

## 8. 阶段四：移动端适配

移动端断点为视口宽度小于 768px，复用现有 DOM。

### 8.1 移动布局

- 顶部资源栏和主导航允许横向滚动，不强行压缩文字。
- 中央内容占满可用宽度。
- 右侧事务栏改为可展开/收起面板。
- 聊天默认收起为底部状态条，展开后显示为底部面板。
- 工坊卡片、设备列表、员工列表、订单、市场和商铺改为单列，确有横向比较价值的局部区域允许横向滚动。
- 弹窗宽度不超过视口，内容纵向排列并可内部滚动。
- 主要点击目标最小尺寸为 44px。
- 使用动态视口高度和安全区，避免浏览器地址栏或底部手势区遮挡按钮。

### 8.2 移动端核心流程

在 390×844 和 430×932 下必须能够：

1. 进入总览并切换主要功能。
2. 参与竞拍并获得原石。
3. 完成开料、规划和精加工。
4. 购买材料、选择镶嵌方案并完工。
5. 购买/选择/维修设备。
6. 查看并招聘员工。
7. 查看藏品，并进入订单或市场处理成品。
8. 展开和收起事务栏及聊天，不遮挡关键按钮。

移动规则不得改变宽度不小于 768px 时的桌面布局。

## 9. 阶段五 A：设备最小闭环

### 9.1 设备目录与获取

- 新档继续赠送三台 1 阶起步设备：
  - 开料：粗加工台。
  - 规划：套件雕刻台。
  - 精加工：精加工抛光台。
- 商铺出售当前 `DEVICE_MODELS` 中九种 1 阶设备，每个工序三种。
- 价格沿用当前 `DEVICE_SHOP_BASE_PRICE`：
  - 粗加工台 9,000；精磨台 12,000；水床切片机 11,000。
  - 套件雕刻台 13,000；数控取件台 16,000；3D 扫描设计台 18,000。
  - 精加工抛光台 12,000；镶嵌一体机 15,000；高光精雕机 20,000。
- 购买成功后新增独立设备实例，不替换已有设备。
- 余额不足时不扣款、不创建设备。

### 9.2 容量与任务

- 所有型号、所有阶数的 `capacity` 永久固定为 `1`。
- 设备属性、型号、阶数均不得提高容量。
- 一台设备有进行中任务时，新的开工请求直接失败。
- 不保存、展示或处理等待队列。
- 同工序多台设备可分别同时加工。
- 员工占用规则仍可能阻止两台设备同时使用同一名员工。

### 9.3 耐久与维修

每个任务完成时，包括碎裂或精加工失败，扣除一次设备耐久：

`耐久损耗 = clamp(round(1 + max(0, 有效风险 - 1) × 5), 1, 3)`

- 耐久范围为 0～100。
- 开工时耐久为 0 的设备直接拒绝。
- 维修恢复至 100。
- 维修费：

`维修费 = ceil(设备基础价格 × 缺失耐久比例 × 35%)`

- 余额不足时不维修、不扣款。
- 本轮没有维修时间、维修材料、随机故障、出售或拆解。

### 9.4 界面

- 商铺现有“建筑与许可”区域内增加设备货架，不改变全局导航。
- 工坊按三工序展示拥有的设备；同工序多台设备均可选择。
- 设备卡显示型号、属性、耐久、状态和 `0/1` 或 `1/1` 负载。
- “换设备”进入商铺并预筛选当前工序。
- 耐久为 0 时显示维修操作，开工按钮不可用。

## 10. 阶段五 B：员工招聘与技能成长

### 10.1 员工与候选人

- 保留当前四名初始员工。
- 员工总数上限为 8。
- 招聘页每批显示 3 名候选人。
- 玩家首次打开招聘页时生成首批候选人，不收刷新费；招聘本人仍需支付招聘价。
- 主动刷新候选人收费 500。
- 候选人由服务端生成：
  - 姓名。
  - 主职：开料、规划、精加工或直播。
  - 品阶：1～5 阶。
  - 九项技能。
  - 正面和负面词条。
  - 招聘价格。
- 候选人品阶权重固定为：1 阶 45%、2 阶 30%、3 阶 15%、4 阶 8%、5 阶 2%。
- 候选人的主职技能为 `clamp(品阶 + 1 + random(0, 1), 1, 7)` 级；其他技能为 `clamp(1 + random(0, min(2, 品阶 - 1)), 1, 5)` 级，初始经验均为 0。
- 每名候选人固定生成一个正面词条和一个负面词条，分别从现有正、负词条池中抽取；姓名从固定姓名池抽取，唯一性由员工 ID 保证。
- 招聘价格：

`招聘价 = 1,500 + 品阶² × 750`

- 余额不足或员工已满 8 人时，招聘失败且候选人保留。
- 招聘成功后只移除该候选人，其余候选人保留。
- 本轮不提供解雇、交易、升阶或特质重洗。

### 10.2 工作占用

- 主职只影响初始技能倾向，不限制员工可参与的工序。
- 一名员工同一时刻只能执行一个加工或直播任务。
- 同一员工可以预先绑定到多台空闲设备。
- 任一绑定设备开工后，该员工进入忙碌状态；其他设备若尝试用该员工开工，服务端拒绝。
- 服务端在实际开工时重新检查忙碌状态，避免重复点击或多窗口并发。
- 任务完成或终止后释放员工。

### 10.3 经验与升级

任务结算时获得经验：

| 行为 | 技能经验 |
|---|---|
| 开料完成 | 解料 `+10`，打磨 `+5` |
| 规划完成 | 修形 `+10`，切料 `+5` |
| 精加工完成 | 雕琢 `+10`，镶嵌 `+5` |
| 直播成功 | 话术 `+10`，控场 `+7`，催单 `+5` |

- 加工任务即使碎裂或精加工失败，也视为完成并获得经验。
- 技能升级阈值为 `50 × 当前等级`。
- 达到阈值后自动升级并保留溢出经验；一次结算可以连续升级。
- 技能最高 10 级；达到 10 级后不再累计经验。
- 品阶本轮保持不变。
- 升级后立即重新计算工分、速度、碎裂防御和直播效果。
- 客户端显示升级提示，并刷新员工卡和技能经验条。

### 10.4 界面

- 填充现有未开放招聘页面，不新增全局导航。
- 候选人卡显示姓名、主职、品阶、关键技能倾向、词条和价格。
- 工坊沿用现有员工选择卡与详情弹窗，增加经验变化、等级和忙碌状态。
- 桌面端整体三栏结构不变；移动端候选人与员工卡纵向排列。

## 11. 阶段五 C：精加工镶嵌闭环

### 11.1 精加工方案

精加工开工请求增加 `finishPlan`：

```js
{
  productType,
  settingId,
  metalId,      // 编绳时必须为 null
  gemId,        // 不配石时为 null
  gemCount,     // 0～12
  polishId,
  backingId     // 不适用时为 null
}
```

支持六种镶嵌方式：

| 镶嵌方式 | 基准金重 | 基准工费 |
|---|---:|---:|
| 爪镶 | 1.5g | 200 |
| 包镶 | 2.5g | 300 |
| 微镶/钉镶 | 3.0g | 800 |
| 槽镶 | 2.0g | 500 |
| 无边镶 | 3.5g | 1,200 |
| 编绳/配链 | 0g | 20 |

支持四种金属：

| 金属 | 库存键 | 增值系数 |
|---|---|---:|
| 足金 24K | `goldPure` | +0.15 |
| 925 银 | `silver925` | +0.03 |
| 18K 金 | `gold18k` | +0.20 |
| 铂金 PT950 | `platinum` | +0.25 |

支持钻石、红宝石和蓝宝石，数量 0～12 颗。每颗增加 `0.05` 增值系数，每颗增加 80 工费；材料按实际颗数从对应库存扣除。

抛光选项：

| 抛光 | 工费 | 增值系数 |
|---|---:|---:|
| 亮光 | 50 | +0.05 |
| 柔光 | 30 | +0.02 |
| 哑光 | 0 | +0.00 |

底托仅适用于蛋面戒指：

| 底托 | 工费 | 增值系数 | 信任影响 |
|---|---:|---:|---:|
| 透底 | 0 | +0.00 | 0 |
| 封底 | 100 | +0.03 | -20% |

封底的信任影响只记录到成品元数据，供订单或后续系统读取；本轮不另做鉴定玩法。

### 11.2 成品、镶法和材质兼容

成品绑定：

- 蛋面：戒指、吊坠、耳坠。
- 雕件：吊坠、耳坠。
- 穿孔件：吊坠。
- 整料：手链、把件。

套件与镶法：

| 套件形态 | 允许镶法 |
|---|---|
| 蛋面 | 爪镶、包镶、微镶、槽镶、无边镶、编绳 |
| 雕件 | 爪镶、包镶、微镶点缀、编绳 |
| 穿孔件 | 包金边、编绳 |
| 整料 | 编绳 |

材质兼容以服务端显式矩阵为准：

| 镶法 | 允许材质 |
|---|---|
| 爪镶 | 18K 金、铂金 |
| 包镶 | 足金、925 银、18K 金、铂金 |
| 微镶、槽镶、无边镶 | 18K 金、铂金 |
| 编绳 | 不选择、不消耗金属 |

显式矩阵是唯一判定来源，避免原始设计中硬度数值和例外说明产生歧义。本轮不加入“软材质允许但随机松脱”的额外随机规则。

### 11.3 成本、扣除与估值

金属消耗：

`金属克重 = roundTo2(镶法基准金重 × (1 + 配石数量 × 0.05))`

现场工费：

`工费 = 镶法基准工费 + 配石数量 × 80 + 抛光工费 + 底托工费`

镶嵌增值系数：

`1 + 金属系数 + 配石数量 × 0.05 + 抛光系数 + 底托系数`

完工价值：

`craftAdjustedValue × 镶嵌增值系数`

其中 `craftAdjustedValue` 是现有精加工工分与设备品质公式执行一次后的结果。实现时移除当前精加工中用于代替真实选择的固定镶嵌倍率，确保员工工分、设备品质和镶嵌方案各计算一次，不重复加成。

材料采购继续使用当前商铺材料目录和库存字段。本轮只把真实库存接入精加工消耗，不扩展材料价格玩法。

### 11.4 原子开工

服务端按以下顺序校验，但只在全部通过后一次性修改状态：

1. 玩家和工坊有效。
2. 设备属于玩家且工序为精加工。
3. 设备耐久大于 0，且当前任务数为 0。
4. 输入套件存在且阶段正确。
5. 员工存在且当前不忙。
6. `finishPlan` 字段完整、数量合法；套件形态由服务端根据输入物类别推导，不接受客户端自报。
7. 服务端推导出的套件形态与成品、镶法、材质组合兼容。
8. 现金足够支付工费。
9. 金属和宝石库存足够。

全部通过后：

- 从原库存取出输入套件。
- 扣除工费。
- 从玩家库存扣除金属与宝石，并把扣除明细保存在任务的 `reservedMaterials` 中。
- 占用设备和员工。
- 创建唯一进行中任务。

任一条件失败时，不产生任何扣除或占用。

### 11.5 完工与失败

成功时：

- 清除任务中的 `reservedMaterials`；材料不再返还。
- 生成最终成品。
- 写入完整 `inlay` 元数据。
- 计算并保存最终价值。
- 发放员工经验。
- 扣除设备耐久。
- 释放设备和员工。

精加工失败时：

- 翡翠输入物退回精加工前库存。
- 按任务中的 `reservedMaterials` 将已扣除的金属、宝石全部退回。
- 人工费不退。
- 正常发放员工经验。
- 正常扣除设备耐久。
- 释放设备和员工。
- 不生成最终成品。

精加工失败只使用当前设备风险、员工词条和技能共同计算出的既有碎裂概率，不再增加独立的镶嵌随机失败。该返还规则只覆盖精加工；开料和规划仍沿用各自现有碎裂规则。

### 11.6 界面与展示

- 在现有精加工区域增加“配置镶嵌”入口。
- 桌面端使用视口内弹窗：套件预览、成品类型、镶法、材质、附加项、成本与估值预览。
- 不兼容选项灰显，并显示具体原因。
- 余额或库存不足时确认按钮不可用并显示差额。
- 移动端同一弹窗改为纵向排列。
- 成品永久保存并在藏品、订单和市场卡片中显示：
  - 成品类型。
  - 镶嵌方式。
  - 金属。
  - 宝石与数量。
  - 抛光。
  - 底托。

## 12. 数据流与错误处理

### 12.1 数据流

```text
玩家点击
  → 客户端提交意图和 requestId
  → server.js 找到玩家并调用领域模块
  → 领域模块完成纯校验与计算
  → server.js 一次性修改玩家状态
  → 写流水/新闻/提示
  → 广播最新服务端快照
  → 客户端按快照重绘
```

涉及现金、库存或占用的请求带客户端生成的 `requestId`。服务端在单个玩家会话内记录近期已处理 ID；后续收到同一 ID 时返回 `DUPLICATE_REQUEST`，不再次修改状态，避免双击造成重复购买或开工。

### 12.2 统一错误结果

领域模块返回：

```js
{ ok: false, code, message, details? }
```

至少包含以下稳定错误码：

- `NOT_FOUND`
- `INSUFFICIENT_CASH`
- `INSUFFICIENT_MATERIAL`
- `CAPACITY_FULL`
- `DEVICE_BROKEN`
- `WORKER_BUSY`
- `ROSTER_FULL`
- `INVALID_COMBINATION`
- `INVALID_QUANTITY`
- `DUPLICATE_REQUEST`

客户端继续使用现有 toast/modal 风格展示中文 `message`；不把内部堆栈或实现细节展示给玩家。

### 12.3 状态恢复

- 校验失败：不修改状态。
- 开工后的正常失败：按各工序规则结算。
- 精加工失败：按第 11.5 节返还翡翠和外部材料，只保留人工费支出。
- 客户端刷新或重新连接：以服务端快照重建界面，不依赖本地临时状态决定资源归属。
