# 镶嵌预览测试台设计

## 背景

当前镶嵌视觉只能在工坊精加工流程中看到。要验证不同套件、成品类型、镶嵌方式、金属和配石的组合，必须先经历暗料、明料、套件规划和开工流程，测试成本太高。

本功能新增一个开发测试用的镶嵌预览台，让调试时可以直接生成预览，不消耗材料、不创建任务、不改变存档。

## 目标

- 提供一个独立测试入口，绕过暗料、明料、套件规划和工坊开工。
- 支持快速切换原料形态、成品类型、镶嵌方式、金属、配石、配石数量和底托。
- 预览必须复用现有真实成品渲染链，确保测试台看到的效果与正式产物一致。
- 提供横向比较视图，能直接看到不同镶嵌方式和材质的视觉差异。
- 测试台只用于本地开发和验收，不参与正式游戏经济。

## 非目标

- 不新增服务器玩法接口。
- 不消耗镶嵌材料库存。
- 不创建工坊生产任务。
- 不重做镶嵌经济和报价模型。
- 不替代正式工坊精加工弹窗。

## 入口

在工坊界面增加一个低干扰的测试入口，文案为“镶嵌预览测试”。入口只打开测试面板，不修改当前工坊选择状态。

面板使用现有游戏弹窗风格，桌面端展示为左右布局，移动端堆叠为上方控制、下方预览。关闭面板后不保留正式游戏状态。

## 交互

测试面板包含一组控制项：

- 原料形态：蛋面、雕件、平安扣、整料类。
- 成品类型：根据原料形态限制可选项，例如蛋面支持戒指、吊坠、耳坠。
- 镶嵌方式：根据原料形态限制可选项，例如整料类只支持编绳/配链。
- 金属材质：根据镶嵌方式限制可选项，编绳/配链不使用金属。
- 配石：无、钻石、红宝石、蓝宝石。
- 配石数量：选择配石后可调 1 到 12。
- 底托：仅蛋面戒指显示，支持透底和封底。

右侧主预览实时展示当前组合。下方提供预览矩阵：

- 镶嵌方式矩阵：展示当前原料形态和成品类型下全部可用镶嵌方式。
- 金属材质矩阵：展示当前镶嵌方式下全部可用金属材质。
- 点击矩阵卡片会同步更新当前控制项和主预览。

无法兼容的组合不展示为可点击卡片；如果用户切换到不兼容的选项，测试台按现有 `normalizeFinishPlanDraft` 规则自动回落到可用组合。

## 数据与渲染

测试台使用 `finishCatalog()` 中的现有镶嵌目录数据，不另建一份规则表。

预览对象使用与精加工弹窗一致的临时成品结构：

- `productType` 表示成品类型。
- `kind` 与 `productType` 保持一致，用于走现有成品分流。
- `components` 包含 `jade`、`mount` 或 `cord`、以及可选 `accentStones`。
- `preview: true` 表示该对象只用于前端预览。

最终 markup 继续通过 `productCanvas()` 输出，并由 `public/inlay-product-renderer.js` 负责组件化镶嵌 SVG。这样测试台不会产生第二套视觉逻辑。

## UI 风格

测试台是工具型界面，不做营销式页面。整体沿用工坊弹窗的边框、间距、字号和夜间主题。

主预览强调玉件主体；矩阵卡片保持紧凑，显示小预览、组合名称和当前选中状态。卡片是重复条目，可以使用轻量卡片样式，但不嵌套卡片。

## 错误处理

- 如果当前目录缺少某类配置，面板显示“暂无可预览组合”，而不是报错。
- 如果金属不适用于当前镶嵌方式，自动清空金属。
- 如果编绳/配链被选中，金属控制显示为“不使用金属”。
- 如果没有选择配石，配石数量自动为 0，并隐藏数量控制。

## 测试

- 模型测试：验证预览变体生成会按形态、成品类型、镶嵌方式、金属兼容性输出组合。
- 控制器测试：验证测试台打开、切换控制项、点击矩阵卡片会刷新临时预览对象。
- 渲染测试：验证测试台产出的预览对象包含组件化镶嵌标记，并复用 `data-jewelry-style="craft-layer"`。
- 浏览器视觉检查：在桌面和移动视口确认面板不溢出，主预览与矩阵卡片可见，切换后视觉更新。
