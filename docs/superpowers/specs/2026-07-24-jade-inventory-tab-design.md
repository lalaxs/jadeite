# 独立库存页签设计

## 目标

将工坊机器详情下方的“阶段库存与成品”抽屉整体删除，并在左侧主导航新增独立“库存”页签。库存页以响应式背包格展示玩家当前可用库存，支持即时搜索、分类筛选和排序，同时保留最终成品“收入藏宝阁”的现有操作。

## 范围

库存页包含：

- `me.rough`：暗料原石与已开料原石。
- `me.materials`：明料。
- `me.slices`：片料。
- `me.bracelets`：精雕毛坯、抛光半成品和最终成品。
- `me.externalMaterials`：持有量大于 0 的金属与宝石；名称、单位、单价和颜色来自 `state.materialCatalog`。

库存页不包含：

- `me.collection` 中已收入藏宝阁的藏品。
- `me.jobs`、`me.polishingJobs` 等加工中的物品。
- `me.livestreamJobs`、交易行挂单等已离开可用库存的物品。
- 持有量为 0 的镶嵌材料。

本轮不新增从库存直接加工、挂牌、直播或交付订单的入口。这些操作仍从各自业务页面进入。最终成品保留“收入藏宝阁”按钮，继续使用现有 `collectBracelet` 行为和服务端校验。

## 页面结构

左侧导航在“工坊”之后增加“库存”页签，使用背包图标。点击后进入独立 `inventory` 视图。

页面从上到下包含：

1. 标题区：显示“库存”和用途说明。
2. 概览区：显示占用格数，以及原石、阶段产物、成品、镶嵌材料的格数。
3. 工具栏：关键字搜索、分类筛选、排序选择和重置按钮。
4. 背包格：按当前结果从左到右、从上到下排列。
5. 空状态：空背包与筛选无结果使用不同文案；筛选无结果时提供重置入口。

背包格在桌面端使用多列网格，在平板与手机端自动减少列数。每格展示预览、名称、阶段或类别、价值或持有数量。最终成品额外显示“收入藏宝阁”。

## 数据归一化

新建独立库存模块，将不同库存桶归一化为统一的客户端视图模型：

```js
{
  id,
  source,
  item,
  name,
  category,
  categoryLabel,
  stage,
  stageLabel,
  typeLabel,
  quantity,
  unitLabel,
  unitPrice,
  totalValue,
  rarityScore,
  backpackIndex,
  isFinished
}
```

`source` 标识原库存桶；普通物品的 `quantity` 为 1，镶嵌材料的 `quantity` 为实际克数或颗数。`totalValue` 对普通物品使用 `value || price || 0`，对镶嵌材料使用 `unitPrice * quantity`。

分类规则：

- `rough`：阶段为 `rough` 的暗料原石。
- `stage`：明料、片料、精雕毛坯和抛光半成品。
- `finished`：阶段为 `finished` 的最终成品。
- `external`：金属与宝石。

## 背包顺序、筛选与排序

默认“背包顺序”固定为：

1. 暗料原石
2. 明料
3. 片料
4. 精雕毛坯
5. 抛光半成品
6. 最终成品
7. 金属
8. 宝石

同一分组内保持服务器数组或材料目录的原始顺序。每个归一化条目保存稳定的 `backpackIndex`，服务器刷新后只要源顺序不变，物品不会无故跳格。

分类筛选支持“全部、原石、阶段产物、成品、镶嵌材料”。搜索忽略大小写与首尾空格，匹配名称、阶段名称、类别名称和类型名称。

排序支持：

- 背包顺序。
- 价值从高到低。
- 价值从低到高。
- 名称。
- 稀有度。

价值相同时回退到背包顺序，保证稳定。稀有度优先使用物品已有品质分、工分评级或品质名称换算；没有品质信息的物品和镶嵌材料按普通档处理，再回退到背包顺序。

## 状态与数据流

搜索词、分类和排序保存在库存模块的浏览器内存中。服务器推送新状态时重新归一化和渲染，但不清空用户当前筛选条件。

工具栏事件只更新本地筛选状态，不发服务器请求。成品“收入藏宝阁”继续通过现有全局动作委托触发；服务端成功后推送新状态，成品从库存页消失并出现在藏宝阁。失败时沿用现有全局提示。

材料目录缺失时，普通库存仍然可用；无法解析目录的材料不凭空编造名称或价格，并在库存页显示材料目录尚未加载的提示。

## 模块边界

- `public/inventory-module.js`：归一化、筛选、排序、筛选状态、模板渲染和库存页事件绑定。
- `public/main.js`：注册 `inventory` 视图、导航图标、DOM 引用、模块初始化和主渲染调用。
- `public/index.html`：提供库存视图容器。
- `public/workshop-module.js`：删除旧库存抽屉、旧抽屉渲染函数及调用。
- `public/styles.css`：库存命名空间下的概览、工具栏、背包格、空状态、昼夜主题与响应式样式。
- `scripts/inventory-module-smoke.mjs`：验证归一化、筛选、排序和渲染契约。
- `scripts/responsive-layout-smoke.mjs`：验证库存格窄屏规则和无横向溢出约束。
- `package.json`：增加库存模块测试并接入完整测试链。

## 测试与验收

使用测试驱动方式完成：

1. 先为归一化、零持有材料隐藏、分类、搜索和五种排序编写失败测试。
2. 实现最小纯函数使模型测试通过。
3. 先为导航入口、独立视图、旧抽屉移除、收藏动作和响应式样式编写失败断言。
4. 接入页面与样式并使 UI 测试通过。
5. 运行完整 `npm test`。
6. 启动本地原型，在桌面和窄屏下实际验证：进入库存、筛选、排序、空状态、收藏成品、工坊机器详情无旧抽屉。

成功标准：

- 左侧“库存”页签可进入且激活态正确。
- 可用库存与正持有量镶嵌材料全部出现，排除藏品和加工中物品。
- 默认背包顺序稳定，搜索、分类和五种排序结果正确。
- 旧“阶段库存与成品”抽屉完全消失。
- 成品可继续收入藏宝阁。
- 手机宽度无横向溢出，控件可键盘操作。
- 完整测试通过，工坊、交易行与藏宝阁无回归。
