# 翡翠经营模拟：移动端布局修复设计

## 目标

修复手机端三个已复现的布局问题，同时保持桌面端现有三栏结构和视觉排版不变：

1. 顶部个人信息卡片在窄屏下超框，资源按钮与主题按钮尺寸、对齐和视觉风格不统一。
2. 工坊选择员工弹窗沿用桌面双栏最小宽度，导致手机端右侧员工详情被裁切。
3. 左侧页签图标和文字偏小，辨识与触控体验不足。

## 已确认方案

采用移动端单栏员工选择方案（方案 A）：员工列表置于上方，完整员工详情置于下方，共用一个可纵向滚动的弹窗。桌面端继续保持左右双栏。

## 响应式布局

### 顶部信息栏

- 仅在 `max-width: 767px` 的移动端规则中调整。
- 玩家卡片、资源按钮、主题按钮统一为 44px 高，并使用一致的圆角、边框和表面色。
- 资源按钮与主题按钮使用固定宽度，玩家卡片占据剩余空间。
- 玩家名称允许收缩，并使用单行省略号保护，避免长名称撑破卡片。
- 适当缩小移动端头像和内部间距，为名称和等级保留稳定空间。
- 不隐藏玩家名称和等级；经验条继续沿用当前移动端隐藏策略。

### 左侧页签栏

- 移动端侧栏宽度由 66px 调整为 72px。
- 页签图标由 20px 调整为 24px。
- 页签文字由 10px 调整为 11px，并略微增加页签高度与图文间距。
- 主导航保持可纵向滚动，底部“事项 / 消息”入口保持现有位置。
- 所有依赖移动端侧栏宽度的内容区域同步使用 72px 偏移，避免遮挡或空隙。

### 工坊员工选择弹窗

- 桌面端保留现有 `320px + 360px` 双栏。
- 移动端将员工选择弹窗改为接近全高的单栏布局。
- 顶部保留标题、搜索和排序；员工列表设置合理的最大高度，详情紧接列表下方。
- 弹窗内容整体可纵向滚动，保证员工头像、属性、天赋、全部技能和确认按钮均可访问。
- 详情底部确认按钮继续保持醒目，并在滚动到详情区域时可稳定操作。
- 不改变员工选择、排序、筛选和确认的数据逻辑。

## 视觉与可访问性

- 顶部三个控件使用现有昼夜主题变量，避免引入新的亮色硬编码。
- 左侧页签的选中、悬停、锁定状态继续沿用现有配色。
- 所有主要触控按钮维持至少 44px 的可触控高度。
- 员工详情的滚动区域不得产生横向滚动条或隐藏内容。

## 验收标准

- 360×800、390×844、412×915 三种手机尺寸下，页面无横向溢出。
- 长玩家名称不超出顶部个人信息卡片，三个顶部控件垂直对齐、风格统一。
- 左侧页签图标和文字明显放大，导航仍可完整滚动访问。
- 工坊选择员工后，可通过纵向滚动查看完整详情并操作确认按钮。
- 1440×900 桌面端顶部、侧栏和员工选择双栏布局与修改前一致。

## 非目标

- 不修改桌面端三栏宽度、导航排版或工坊弹窗双栏结构。
- 不调整员工数值、技能、天赋或工坊生产逻辑。
- 不重做顶部资源信息内容，仅修复移动端尺寸、对齐和收缩行为。
